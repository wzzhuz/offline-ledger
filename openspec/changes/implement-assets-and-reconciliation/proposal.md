# 实现资产看板与对账流程

> **本文件是 change 的上下文入口。**
> 新会话只读这一份文件，就应当能还原本次改动的全貌，无需重新讨论。

## 为什么改

**背景（使用者原话与项目现状）**：

- 使用者最初的诉求只有两句核心：「**知道自己的资产情况和支出情况**」、
  「**资产数据是高度敏感数据，不信任第三方**」
- 在 Firefly III 出现过「与实际余额**差 1 分钱**，但账单太多、核算找到这笔
  太费事，最后直接记了一笔虚拟支出让余额一致」。使用者明确表态：
  **数额太小可能直接不关注，记一笔虚拟支出；几十块就要找到这笔交易**
- 阶段 0 / 1 / 2 均已完成并归档，8 个模块 / 93 条 Requirement / 116 个 Scenario，
  CI 全绿（run `fa7d33e6ff`），已产出约 22.5 MB debug APK。现在能记一笔、
  翻明细、组合筛选、恢复删除、导出明文 JSON
- **但资产页与统计页仍是明确标注「阶段 3 / 4」的占位页**。
  「资产状况可见」这个最原始的诉求还没有落地
- 阶段 2 归档时记录了一笔**规格债**：两条只描述阶段 2 临时状态的 Requirement
  （资产页显示占位说明、筛选面板没有对账入口）在阶段 3 落地后会与实际行为相反，
  必须用 MODIFIED 替换

**问题**：数据层已经把锚点字段、独立校准表、带符号余额全部备好，
但用户既看不到净资产，也没有「差 1 分钱就一键抹平、差几十块就反查」的路径。
阶段 3 是把「能记账」变成「能看懂自己的钱」的分水岭。

## 做什么

1. **资产页替换占位**：净资产看板、总资产 / 总负债展示、可用额度、
   资产账户 / 信用负债账户分组、账户详情（专属流水 + 余额调整记录折叠 / 撤销）、
   新增账户 / 改名 / 归档 / 计入净资产开关
2. **对账流程**：输入实际余额 → 差额 → `|差额| ≤ 1.00 元` 一键「忽略尾差并校准」；
   `> 1.00 元` 先引导进入核对视图，仍选择校准时备注必填
3. **核对视图**（资产页内 Dialog，不新增 Tab）：对账锚点后流水切片 +
   7 / 30 / 90 天放宽、金额反查（等于 / 区间 / 近似 ±1.00 元）、
   疑似问题标记（金额 0 / 未分类 / 异常大额 / 同账户同金额短时重复）、
   「只看疑似项」开关、无匹配时明确提示「未找到 0.01 的记录」
4. **校准生成独立 `BalanceAdjustment`** 并在同一事务内推进锚点 + 重算余额；
   不生成伪支出、不进明细 / 分类 / 年报
5. **两条规格债用 MODIFIED 修复**：`reporting-ui`「四 Tab 骨架一次成型」、
   `reconciliation`「阶段边界明确」
6. 纯 JVM 对账引擎 + 单测，DAO 追加参数化查询，事务检查清单扩展

## 不做什么

- ❌ **不改表结构**：`AccountEntity` / `BackupAccount` 在阶段 1 已预留
  `lastReconciledAt` / `lastReconciledBalanceCents`，`AppDatabase` 仍 `version = 1`，
  **无 Room Migration**；备份格式与 `schemaVersion = 1` 一字不动
- ❌ 不改 4 Tab 导航结构、不改阶段 2 明细页 / 记一笔 / 回收站
- ❌ 统计图表（阶段 4）：环形图、下钻、月度趋势、年度双线
- ❌ 阶段 5 功能：SAF 加密导入导出、CSV、应用锁、分类管理、
  账本健康偏好页、**阈值可配置 UI**（本阶段阈值写成常量）
- ❌ 明文导出入口本阶段保留，阶段 5 再替换
- ❌ v1.1 清单：模板 / 周期账、快捷方式与小组件、预算、退款报销、
  多币种混算、三级及以上分类、账单导入
- ❌ 不新增任何依赖（Compose / Room / Hilt / Paging 均已具备）
- ❌ 不引入 Vico / Coil / Glide / 任何网络或上报 SDK
- ❌ 不改 `wzzhuz/my-app-workflow`、不改 `docs/设计规格书_v2.md` 历史快照
- ❌ 不在沙盒内编译 APK 或真机测性能（无 SDK / 模拟器）

## 对齐结论

> 阶段 0 在对话里产出，五项齐全才进入写作。

1. **要解决什么问题**
   把最原始的两个诉求真正落地：**「知道自己的资产情况」**（净资产 / 总负债 /
   可用额度 / 账户明细）与**「差 1 分钱不用翻遍账本」**（阈值分流、对账锚点、
   金额反查、核对视图）。这是从「能记账」到「能看懂自己的钱」的分水岭。

2. **范围边界**
   - 改：资产页真内容、账户管理、对账流程、核对视图、DAO / Repository 新方法、
     纯 JVM 对账引擎与单测、两条 MODIFIED、README / 检查脚本
   - 不改：表结构、备份格式、导航结构、阶段 2 UI、图表、阶段 5 功能、v1.1 清单

3. **关键约束**
   净资产 MUST 为 `SUM(balanceCents WHERE includeInTotal = 1)`，
   **禁止「总资产 − 总负债」**；总负债仅作展示 `ABS(SUM(LIABILITY))` 且
   MUST NOT 参与计算；可用额度 = `creditLimitCents + balanceCents`（负债余额本就为负）。
   校准 MUST 生成独立 `BalanceAdjustment`，MUST NOT 生成 EXPENSE / INCOME 伪流水，
   不进明细 / 分类 / 年报；撤销后重算回退。
   差额 = 实际 − 账面，全程 `Long` 分 + `BigDecimal` 输入，禁止浮点。
   锚点推进与校准 MUST 同处一个 `withTransaction`；
   **锚点只用于缩小核对范围，不参与余额计算、不锁定锚点前流水**
   （否则破坏「余额可全量重算」）。
   金额反查与疑似标记的基础数据集 MUST 由参数化 SQL 限定（账户 + 锚点后 +
   金额区间），MUST NOT 全表加载后 Kotlin 过滤。
   **无 Room Migration**：`version = 1` 不变，仍禁止 `fallbackToDestructiveMigration`；
   导出备份自动带锚点字段，信封头部一字不改。
   沙盒无 SDK / 模拟器，编译与单测由 Actions 验证；推送用单次 commit；
   Python 拼 Kotlin 后必跑五个检查脚本；不声明 `INTERNET`。

4. **验收标准**（可测）
   - **GIVEN** CI 跑完 **THEN** 五个静态检查 / 单测 / debug / release(lintVital) 全绿，
     且 Actions 列表能查到该次运行
   - **GIVEN** 资产 10000 分 / 信用卡 −500 分 **WHEN** 打开资产页
     **THEN** 净资产 9500 分、**不是** 10500 分
   - **GIVEN** 账面 1000.00、实际 999.99 **WHEN** 一键校准
     **THEN** 生成 `deltaCents = −1`、当月支出 / 年报 / 餐饮分类均不变、锚点推进
   - **GIVEN** 差额 38.50 > 阈值 **WHEN** 打开对账
     **THEN** 先出现「核对」入口与锚点后条数，**不**直接出现一键抹平按钮
   - **GIVEN** 输入 38.50 反查 **THEN** 列出 `amountCents = 3850` 的流水；
     反查 0.01 无结果时明确提示「未找到 0.01 的记录」
   - **GIVEN** 撤销一条校准 **THEN** 余额回到校准前
   - **GIVEN** 导出 JSON **THEN** 锚点字段仍在、重新解析后余额一致
   - **GIVEN** 归档阶段 3 **WHEN** 校验 specs **THEN** 两条阶段限定 Requirement
     已被 MODIFIED 替换、无矛盾要求
   - **GIVEN** 推送完成 **WHEN** 用 API 校验 **THEN** sha 一致、无 token 明文

5. **被否决的方案**
   一句话结论：**所有「跳 change / 为锚点改表结构做 Migration / 校准伪装成支出 /
   锚点存 SharedPreferences / 锚点参与余额计算 / 全表加载后 Kotlin 过滤 /
   核对视图做成第 5 个 Tab / 顺手做图表与 CSV / 物理删除有流水的账户 /
   本阶段做阈值配置 UI」的方案均被否决**，
   采用「零表结构变更 + 独立校准 + 锚点事务 + 资产页内 Dialog 核对视图 +
   参数化范围 SQL + 阈值常量」。完整表格见 `design.md`「考虑过的其他方案」。

## 影响范围

**触及的 spec 模块**：`reconciliation`（主）、`money-precision`（净资产公式落地）、
`ledger-transactions`（reconcile 事务）、`reporting-ui`（MODIFIED）、
`backup-restore`（锚点随备份）、`build-and-ci`（单测与检查清单扩展）。

**是否需要重新安装包**：否（签名未变，数据库结构未变，无 Migration）

**是否会丢数据**：否（本阶段不改表结构、不改备份格式、不删除账户）

**行为变化**：资产页从占位说明变为真实净资产看板与对账入口；
统计页仍为阶段 4 占位；其余页面行为不变。
