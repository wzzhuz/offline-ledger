## ADDED Requirements

### Requirement: 批量规整采用动态规则编辑器且可逐字段撤销
规则 SHALL 由「字段 ▾ + 操作符 ▾ + 按类型分派的值控件」的动态行编辑器产生，
MUST NOT 以固定槽位表单枚举可用条件与动作。条件字段 SHALL 至少包含交易对方、
分类、备注、金额、账户、日期、币种、导入来源、不计入收支；操作符 SHALL 按字段动态给出，
并支持取反与 ALL / ANY。动作 SHALL 支持设置分类、交易对方改为、备注替换 / 追加、
切换不计入收支，一条规则可叠多个动作。

分类与账户的值 MUST 由弹窗按 id 选择（含停用与归档项，显示「一级 / 二级」），
交易对方与备注 MUST 提供 DAO 限量联想；MUST NOT 靠键盘手打目标分类名，
否则 v0.2.14 换过分类清单后必然对不上名。规则 MUST 可保存、按组内 sortOrder 有序、
可启停 / 编辑 / 复制 / 删除；「保存并立即应用到历史」SHALL 在保存后直接走同一
预览 → 单事务 → 末尾重算 → 撤销链路。

规则列表 SHALL 为独立全屏页，编辑器 SHALL 为另一独立全屏页，两者 MUST NOT 同页滚动堆叠；
规则列表 MUST 提供设置一级入口（排在「数据与备份」之后），「数据与备份」内 MUST NOT 再保留
「批量调整 / 批量规整」入口；拆页 MUST NOT 新增 NavHost 路由或动 4 Tab 骨架。
已保存规则 MUST 可从列表再次「应用」到历史记录，应用 MUST 先进入「查看匹配记录」页给出
命中数与前后对比，确认后 MUST 走同一单事务 → 末尾重算 → changeset 逐字段撤销链路；
「查看匹配记录」MUST NOT 被当成规则详情，「编辑」才是唯一详情入口；列表 SHALL 显示上次应用结果。

分类迁移 SHALL 复用同一规则引擎，以「批量录入」一次生成 N 条普通规则并给出
每组命中数 / 冲突组 / 未命中报告，MUST NOT 另开写入口或第二套执行引擎；
删掉独立映射表入口 MUST NOT 丢失此前已生成的规则。

所有写入 SHALL 先给出命中条数与前后对比，确认后 MUST 在单事务内写入并末尾重算；
变更 MUST 生成 `changeset` 保存每个受影响字段的变更前值，撤销 MUST 逐字段还原。
禁止静默改写历史；一期禁止导入后自动触发、嵌套条件、表达式引擎与 stop processing。

#### Scenario: 旧分类一次迁移到新分类
- **WHEN** 使用者配置「条件 = 分类等于旧类 → 动作 = 设置分类为新类」并保存后立即应用
- **THEN** 该旧类下全部流水改为新类，前后对比与撤销逐字段一致

#### Scenario: 同名二级不串味
- **WHEN** 两个不同一级下都有名为「其他」的二级分类
- **THEN** 分类弹窗显示「一级 / 二级」全名，按 id 选中，命中集合互不混淆

#### Scenario: 条件互不串味
- **WHEN** 同时设置对方包含、分类等于、金额区间与导入来源
- **THEN** 只命中同时满足全部条件的记录；任一条件留空不会命中全库

#### Scenario: 批量录入与单条规则共用引擎
- **WHEN** 用批量录入一次生成 N 组「旧分类或对方关键词 → 新分类」
- **THEN** 生成 N 条可编辑的普通规则，预览 / 写入 / 撤销与单条配置完全一致


## 决策史

### 第 36 批（v0.2.18）：规则 2.0
借 Firefly III 的「条件组 + 动作组 + 规则组有序 + strict/非 strict + 回溯应用」模型，
落地可保存规则、ALL/ANY、取反、七种操作符、多动作、`rule_groups` + `rule_definitions`
两张零外键表（`version = 4`）与备份 DTO 往返。**但该批把能力做进了引擎，UI 却退化成
「对方包含 ___ / 改到分类 ___」几个写死槽位**，使用者无法自选字段；并另开了
「分类迁移映射表」独立入口，与「分类调整就是一条普通规则」的直觉相悖。
本段仅作决策史，**实现口径以第 37 批为准**。

### 第 37 批（v0.2.19）：三段式动态编辑器
按使用者提供的 Firefly III 三张截图对齐：条件下的拉把「字段 + 操作符」合成一个超长单选
（文字截断、含 SEPA / 对账 / 日志 ID 等本项目没有的字段），窄屏四列表格也挤压；
本项目改成**两级短选择 + 卡片式动态行 + 按类型分派的值控件**，规则页升为独立全屏页。
FF3 的 `description` 对应本项目「交易对方」、`notes` 对应「备注」，
「设置目标账户」映射成「交易对方改为」，因此**不加独立 description 列、不改表**。
`stop processing` 不做（规则组有序 + 首次命中优先已能兜冲突），只借
「运行此规则」→「保存并立即应用到历史」。

| 项 | 落地 |
|---|---|
| 目录单一来源 | `RuleEditorCatalog`：字段 → 操作符 / 值控件、动作 → 值控件，UI 与单测共用 |
| 值控件 | 分类 / 账户弹窗（含停用与归档、显示全名、搜索）；对方 / 备注 DAO 限量联想 + 200ms 防抖；金额 / 日期上下限；布尔勾选 |
| 入口归并 | 删独立映射表 UI，改「批量录入」生成普通规则；`CategoryMigration` / `migrationReport` 保留为纯 JVM 兼容代码，不再作为第二套写入口 |
| 不回退 | `RuleEngine` / `applyBulkTargets` / `changeset` / 两张规则表 / `version = 4` / 备份 DTO 与恢复拓扑序 / 预览 → 单事务 → 末尾重算 → 撤销 |
| 不做 | `description` 独立列、改账户动作（会动余额口径）、触发器自动跑、表达式引擎、stop processing |

**测试**：`RuleEditorCatalogTest` 4 条（目录完整性 / 批量生成普通规则 / 命中冲突未命中报告 /
经同一引擎应用与撤销）、`RuleEngineFieldsTest` 4 条（按 id 匹配分类、账户币种来源布尔字段、
NOT_EQUALS 与取反组合、金额日期区间）。

**零改表 → v0.2.18 上覆盖安装即可，不用卸载。**

### 第 38 批（v0.2.20）：列表与编辑器分家、保存后可再次应用

v0.2.19 把规则做成了独立全屏页，但列表与编辑器仍堆在同一滚动 Column 里，
「预览」又被当成既像详情又像命中检查的模糊按钮，且保存后没有任何再次执行入口。
本批只改编辑态与导航：`RuleListScreen` 以设置内二级页状态栈切换列表 / 编辑器 /
查看匹配记录三个独立页面（零新增 NavHost 路由）；设置页新增「规则列表」一级入口，
删掉「数据与备份」里的「批量规整」旧门；列表行提供「应用」与「编辑」两种语义，
应用复用 `previewRule` / `previewGroup` → `commit` → `revert` 的既有链路。
`RuleEngine` / `applyBulkTargets` / `changeset` / `rule_groups` + `rule_definitions` /
`version = 4` / 备份 DTO 与恢复拓扑序一个不动，**零改表 → 覆盖安装即可**。

**回退顺序**：若二级页状态栈在旋转后丢态，`rememberSaveable` 保底；若「应用」与新建时
预览出现两份写入口，一律收敛回 `RuleViewModel.previewRule` 单一出口；不新建写入口。
