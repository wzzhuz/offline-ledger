# 变更提案：Firefly III description 独立字段

## 为什么

FF3 的 `description` 是必填，很多交易内容写在里面，而交易对方常被当作占位维度（例如「虚拟-不记录」）；`notes` 另有信息。当前导入只保留对方与备注，导入后无法看懂「这笔干嘛的」。使用者明确要求不把 description 并入备注。

## 做什么

- `records` / `trash` 加独立 `description` 列（`version = 5`，测试期无迁移，卸载重装先导出）
- FF3 `description` → 新列，`notes` → 现有备注，对方占位名原样保留
- 自有 CSV 11 → 12 列；导出/重建全链路带上，旧文件缺列按空串兼容
- 加密备份 / 自动快照：`BackupRecord` 带默认值，`BackupSchema.CURRENT` 升 5，旧备份缺键不炸
- 记一笔加「描述」输入（placeholder-only、非必填）
- 明细列表主标题动态回退：有描述用描述、空着用交易对方（2-A'）
- 筛选面板「描述包含」复用单条参数化 SQL；规则字段目录加「描述」条件 / 联想 / 「描述改为」动作

## 不做什么

不并入备注、不覆盖对方、不动统计口径与 Top5 对方聚合、不引第三套导出格式、不动规则求值与 changeset 撤销链路。
