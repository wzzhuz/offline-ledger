# rethink-record-entry-layout（第 77 批 + 第 80 批，一并归档）

## 为什么

**第 77 批（v0.2.56）**：真机反馈「记一笔元素越来越多、看着杂乱」。核查
`RecordEditorDialog.kt`（984 行）首屏铺了 12 个视觉块、只有 2 处折叠，
两个带框输入框叠起来近 150dp 比金额还重。同时 Q4B 要求全 App 上动态色 +
edge-to-edge，与第 69–70 批「定死浅灰底 / 纯白卡 / 清新蓝」口径直接冲突。
当时把低频项收进唯一的「更多 › + MorePanel」。

**第 80 批（v0.2.59）修订**：真机对照一羽记账 4 张截图后，使用者反馈
「模板、账户、优惠、不计入、标签、备注，是否也像一羽那样放在数字键盘上方，
有需要时才点击弹出选择，省去『更多』这一层展开再选的操作」，
并指出「我们会设置默认账户，账户通常不需要选择，点击频率也会相应降低」。
核查三点：
- 模板实测要 `更多 › → 模板 › → 全部模板 AlertDialog → 关面板` **3～4 次点击**，
  而第 77 批 delta 白纸黑字写「两次点击完成预填」；
- 账户有 `LedgerPrefs.defaultAccountId` 预填，却仍在首屏占一整行表单；
- 收款方联想 chips 被 Q3A 移进 MorePanel，与「输入上下文」彻底分离，
  主 spec 老 Scenario 还写着「输入框下方出现 chips」——三处规格腐烂。

**结论**：第 77 批把低频项全塞进「更多」是降噪过头，**层数比空白更伤低摩擦**。
一羽的做法是「入口常驻但内容按需弹出」。本 change 因此整块修订后一并归档。

## 改什么（最终形态）

- 键盘上方固定**单行 5 枚 chips**：账户 / 模板 / 备注 / 标签 / 优惠（转账为手续费）。
  「不计入收支」并入备注 sheet，不占第 6 枚；每枚 ≥40dp 点击区、编辑态带旧值摘要。
- 撤掉「更多 ›」入口与 `MorePanel`；每枚 chip 直接开自己的底部 sheet
  （`Dialog` + `Alignment.BottomCenter` + 20dp 圆角 Surface + 拖拽把手）。
- 账户从首屏表单行移到 chips（默认账户预填），sheet 改两列网格 + 余额 + 搜索；
  转账态 sheet 内两个 `FilterChip` 分段转出 / 转入。
- 模板 sheet 一行一条给出名称 / 备注 / 预填金额，点一项预填草稿并关闭，
  **2 次点击**，MUST NOT 自动落库。
- 收款方联想 / 常用回到输入框**正下方**一条 40dp 内联条，仅聚焦或有内容时出现，
  空输入给常用、有输入给模糊联想，互斥共用一条，ViewModel 零改动。
- 保留第 77 批的分类快捷栏、收款方/描述无边框内联、金额单独大字号、
  日期无标签副行、整数分键盘、动态色一行回退、edge-to-edge insets 避让。

## 不改什么

- 分类快捷栏、默认账户预填机制、上次分类/时间记忆、整数分键盘、金额真相源、
  优惠/手续费数据模型、标签关联表、模板「预填草稿」语义、统计口径、
  备份/CSV/Firefly 往返、全部 Room 表结构。
- 零改表（`version = 8` 不变）→ v0.2.58 直接覆盖安装。
- 不引入 `ModalBottomSheet` 等实验性 API（T12 惯例）。
- 不新增 Navigation 路由、不改 4 Tab、不做长按拖拽排序（踩坑清单 §3.1 手势坑）。
- 一羽只借交互，**不借报销 / 应付等本项目没有的业务字段**。

## 对齐结论（阶段 0，五项）

| # | 项 | 结论 |
|---|---|---|
| 1 | 要解决什么问题 | 撤掉「更多」中间层，低频项从键盘上方 chip 直达；顺带修复模板 3～4 次点击与 spec「两次点击」的偏差、把收款方联想放回输入上下文 |
| 2 | 改什么 / 不改什么 | 见上两节。只改 `ui/record/` 的入口组织、`check_record_layout.py` 与文档；数据层 / 聚合 SQL / 保存链路 / 分类快捷栏 / 零改表 / 4 Tab 一律不动 |
| 3 | 关键约束 | 三条铁律（数据是你的 / 账要算得准 / 记账不能变慢）；点击区 ≥40dp；不用实验性 API；一羽只借交互不借业务字段；第 77 批 delta 未归档需一并收口；沙盒不编译 APK，走 GitHub Actions |
| 4 | 验收标准 | 12 个静态检查 + 单测 + Debug + Release lintVital 全绿；真机确认「两次点击完成模板预填」「首屏无需上滑仍能看到描述与保存」「输入收款方时联想同屏可见」「编辑态旧备注/优惠/标签不丢」 |
| 5 | 被否决的方案及原因 | 6 项两行全平铺（净增约 40dp，首屏风险高）；联想常驻键盘上方 chip（占空间、脱离输入上下文）；新做长按拖拽排序（历史手势坑）；`ModalBottomSheet`（实验 API）；详见 `design.md` |

**使用者三项确认**：① A 单行 5 枚 chips；② 并进同一个 change 一起归档；
③ 联想条放回输入框下方、常用与联想互斥共用一条。

## 验收与实测

- 第 77 批：`45746395557` / `45747016651` 全绿，v0.2.56 包
- 第 80 批：见 `tasks.md` 实测段（本 change 归档时回填）
- 零改表，全程覆盖安装；12 个静态检查全 PASS
- 真机待验项保持 `[ ]`，CI 全绿不替代观感验收

**理由**：本 change 第 77 批已完成实施与出包，第 80 批按使用者真机反馈整块修订；
两批共用一份四件套与 delta，归档时一次合并回 specs，避免两层 delta 打架、
也避免「只挪目录不合并 delta」的规格腐烂。
