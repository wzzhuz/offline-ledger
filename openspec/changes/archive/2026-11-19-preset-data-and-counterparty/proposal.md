# 预置数据与交易对方归一（第 30 批）

## Why
- 预制账户（微信零钱 / 支付宝 / 招行卡）是代码写死的，首次启动就被绑住；使用者希望改成「常用银行 / 支付宝 / 月付」的快捷创建，并用卡号后四位区分同名卡。
- 预制分类清单不够本土化，且缺少租房 / 养车 / 养宠物场景；使用者希望按钱迹 / BeeCount 的两级习惯重排，并能「暂时隐藏不关注的、有需要再启用」。
- 支付宝 / 微信账单里的商户全称（如「南京盒马网络科技有限公司」）与手工记的简称不匹配，跨来源对账的疑似匹配命中率低。
- 按使用者 2026-11-18 重申：测试阶段重装、改表均可接受。

## What Changes
- 删除 `SeedData.accounts` 预制行，首次启动零账户；新增只读 `AccountTemplates` 快捷模板（资产组 / 信用负债组），卡号后四位作为账户可选字段。
- 分类清单挪到随包 `assets/default_categories.json`（唯一可替换来源），`SeedData` 保留同构 fallback 与纯 JVM 校验；新增 `categories.enabled`。
- 按 **A 方案**：居住只放租房 / 自住成本；代缴父母水电归到「人情 / 赡养·代缴水电」；养车、宠物独立一级；取消每个一级下的「其他」二级。
- 分类管理加「启用 / 停用」，记一笔、筛选面板、预算、模板只列启用的；统计、排行、历史、CSV / 备份仍读全量。
- 新增 `counterparty_aliases` 轻量表，CSV / Firefly III 导入落库前把商户全称归一成简称；`records.counterparty` 仍是自由文本，不建 FK、不引对方管理页。
- `AppDatabase.version` 2 → 3，无迁移，**必须卸载重装，装前先导出**。

## Capabilities
- `category-stats`：预置清单可替换、启用开关语义、A 方案分类结构。
- `ledger-transactions`：快捷账户模板、商户别名归一、清单消费方逐处核对。
- `backup-restore`：导出 / 重建仍读全量分类，不因停用丢失历史。

## Impact
零新增依赖、零新增权限、Manifest 不变；表结构变更 → 覆盖安装会开库失败。
