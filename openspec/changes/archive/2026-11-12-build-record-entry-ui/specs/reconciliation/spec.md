# Delta for 对账与核对

## ADDED Requirements

### Requirement: 明细提供基础组合筛选

明细 SHALL 提供筛选面板，支持时间范围 + 账户 + 类型 + 一级 / 二级分类 +
金额区间 + 备注全文的组合条件，并 SHALL 提供「清空筛选」。
筛选结果 SHALL 复用唯一统计口径，已移入 `trash` 的流水 MUST NOT 出现。

#### Scenario: 缩小核对范围

- **GIVEN** 用户怀疑某账户上月漏记一笔餐饮支出
- **WHEN** 设置时间 + 账户 + 一级分类 + 金额区间
- **THEN** 返回符合条件的流水
- **AND** 备注全文搜索可进一步定位

#### Scenario: 清空筛选

- **GIVEN** 已设置 4 个筛选条件
- **WHEN** 点「清空筛选」
- **THEN** 恢复为当月全部流水
- **AND** 概览仍显示整月聚合值

**理由**：组合筛选是阶段 3「对账锚点 + 金额反查」的底座。
本阶段只做基础筛选面板，锚点与反查仍属阶段 3，不得提前塞入。

---

### Requirement: 阶段边界明确

对账锚点、阈值分流、金额反查与疑似问题标记 SHALL 留到阶段 3 实现，
MUST NOT 在阶段 2 以「顺手做掉」的方式提前加入。

#### Scenario: 阶段 2 打开筛选面板

- **GIVEN** 阶段 2 版本
- **WHEN** 查看筛选面板
- **THEN** 有金额区间与备注全文
- **AND** 没有「按差额反查」与「对账锚点」入口

**理由**：范围蔓延是个人项目烂尾首因；锚点需要 `lastReconciledAt`
的写入流程，应与阶段 3 的资产页一起做。
