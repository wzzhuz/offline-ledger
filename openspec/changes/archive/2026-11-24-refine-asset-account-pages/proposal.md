# 资产账户列表与新建账户页借鉴一羽记账的布局优化

> 本文件是 change 的上下文入口。新会话只读这一份文件，

## 日期

2026-11-24

## 为什么改

使用者给出三张**一羽记账**截图（资产账户列表 / 添加资产账户 / 选择银行弹窗），
要求「账户列表和新建账户的 ui 也参考一羽记账优化一下」，并拍板
**Q1A Q2A Q3A，按上表做**。

### 先收回上一轮的一处误判

上一轮对齐分析把这三张**参考图**误读成了「本 App 现状」，写出「顶部蓝底概览已有雏形」
「表单字段清晰（计入总资产 / 隐藏 / 默认使用）」「银行选择弹窗信息密度高」等描述——
**这些都是一羽的界面，不是本 App 的**。核查 `AssetsScreen.kt` 后，本 App 真实实现是：

- 资产页为白底 `headlineMedium("资产")` + 白底 `Card`「按币种的资产小计」
  + 「账户（N）」计数 + 「含已归档」chip + 文字「+ 新增」；分组是灰色
  `SectionTitle` + 纯行 `AccountCard`；行下方横排 5 个 `MiniAction`
  （详情 / 对账 / 编辑 / 归档 / 删除）+「≡」拖柄 +「⋮」菜单。
- 新建 / 编辑账户是 `AlertDialog` **小弹窗**：12 个 `FilterChip` 快捷模板
  （`chunked(3)`）+ 名称 + 卡号后四位 + 类型 chips + 期初余额 + 信用额度。
- **没有**账户图标、**没有**银行选择弹窗、**没有**备注 / 隐藏账户 / 默认使用字段、
  **没有**蓝底 TopBar 与底部大保存按钮。

因此本轮是「拿一羽做目标，把本 App 现状朝它靠」，不是「给已有页面降噪」。
上一轮表里「不改隐藏 / 计入总资产 / 默认使用语义、银行图标数据来源（IconFont）」
属于把参考图的功能当成了本 App 已有功能，本批**不新增这些业务字段**，
只做 UI 等价落地，逐项在 design 里说明。

### 一羽可借鉴的组织方式

蓝底顶部身份区 + 分组标题小竖条、图标圆 + 名称 + 金额右对齐的紧凑行、
信用账户「无欠款 / 可用」副文案、底部拇指区主操作、模板选择做成聚焦的底部 sheet。
**借的是层级、密度与操作路径，不借数据口径与在线能力。**

## 改什么

- **Q1A 列表**：保留现有 4 Tab、按 `AccountType` 分组、`LazyColumn` +
  `reorderable` 骨架；顶部改蓝底身份区（仍按币种分组显示小计），分组标题加强
  （蓝色小竖条 + 账户数），账户行改「图标圆 + 名称/卡号后四位 + 金额右对齐 +
  副文案」紧凑布局；5 个横排文字操作收进「⋮」菜单，「≡」拖柄改为整格长按拖动。
- **Q2A 新建**：`AddAccountDialog` 从 `AlertDialog` 小弹窗改为近全屏
  `Dialog`（`usePlatformDefaultWidth = false`），蓝底 TopBar「← 添加资产账户 / 保存」、
  分组小竖条、「图标 + 账户名称」紧凑小卡、底部大保存按钮；
  **表单字段与顺序不变**（名称 / 卡号后四位 / 类型 / 期初余额 / 信用额度），
  `onConfirm` 签名与 `AssetsViewModel.addAccount` 零改动。
- **Q3A 模板选择**：把主表单里的 12 个 `FilterChip` 收进新增的
  `AccountTemplateSheet` 底部 sheet：标题 + 一行精简提示 + 按
  `AccountTemplate.group` 分组 + **2 列**图标网格 + 底部「自定义名称」入口。
  点选只回填 `name` / `type`，零写库、零改表。
- 版本号 `0.2.39 → 0.2.40`；同步活文档 §7.41 / §8 第 59 批、`project.md`。

## 不改什么（硬约束，逐条核对基线）

| 基线 | 约束 | 本批做法 |
|---|---|---|
| `reporting-ui`「资产页按币种分组且移除单一净资产总数」 | MUST NOT 显示跨币种单一「净资产」总数 | **不照抄**一羽「净资产 ¥8944.00」；蓝底区仍**每个币种一组**显示资产 / 负债 / 小计 |
| `reporting-ui`「管理类页面入口固定且列表与编辑分离」 | 资产页账户行 SHALL 为纯行、MUST NOT 用 Card / 阴影；行操作 SHALL 收进紧凑菜单 | **不照抄**一羽分组白卡；保留纯行 + `ListDivider()`，把 5 个横排 `MiniAction` 收进「⋮」 |
| `reporting-ui`「四 Tab 骨架一次成型」/「资产页按币种分组…」 | 4 Tab 结构不变 | 不加路由、不加第 5 Tab；新建页用 `Dialog` 实现全屏视觉，不动 `LedgerApp` |
| `ledger-transactions`「快捷账户模板替代预制账户行」 | 新增账户 SHALL 提供只读模板，按资产组 / 信用负债组展示，点选自动填名称与类型，可填卡号后四位 | 模板改由 sheet 承载，**语义全部保留**；整块 MODIFIED 该 Requirement |
| `reporting-ui`「资产页提供账户编辑且可改期初余额与币种」 | 编辑支持名称 / 期初 / 币种 / 额度 / 计入净资产 | `EditAccountDialog` **本批零改动** |
| `money-precision` 净资产 / 可用额度口径 | 按 `includeInTotal` 求和；可用额度 = 额度 + 负余额 | 只用既有 `Reconciliation.availableCredit`，不新算 |
| `privacy-security`「不声明网络权限」 | 当前 Manifest 不声明 `INTERNET`；联网能力 SHALL 先在 `project.md` 显式授权（用途 / 数据流向 / 用户控制），**这不是形式禁令** | 本批不申请授权，MUST NOT 引入在线图标下载；**不照抄**一羽「IconFont 下载 PNG」；账户图标复用 `CategoryIcon` 中性圆 + 首字，零新增资源 |
| 全站零表结构变更 | `AccountEntity` / `version = 5` 不动 | 不新增备注 / 隐藏 / 默认使用 / 图标字段；账户图标按 `name` 与 `type` 在 UI 层即时计算 |

`CategoryIcon` 已忽略 `colorHex`（`@Suppress("UNUSED_PARAMETER")`），
账户图标天然是中性圆 + 首字，**不引入彩色图标、不引入银行 logo 资源**，
与「记一笔页图标效果差」的既有口径一致。

## 五项对齐结论

1. **问题**：资产账户列表与新建账户页的观感、密度与操作路径不如一羽清爽。
2. **范围**：三处 UI（列表 / 新建 / 模板 sheet）；不改数据模型、不改统计口径、
   不改 4 Tab、不加在线图标、不加业务字段。
3. **约束**：见上表七条基线；`reorderable` + 上移/下移无障碍兜底保留；
   `ListDivider()` 单一来源保留；CI 全绿不替代真机。
4. **验收标准（13 条 → 本 change 新增 6 条）**：
   (a) 顶部蓝底区按币种分组显示小计，MUST NOT 出现跨币种单一净资产总数；
   (b) 分组标题带小竖条与账户数，账户行仍是纯行 + `ListDivider()`；
   (c) 账户行图标 + 名称 / 卡号后四位 + 金额右对齐，信用负债显示「无欠款 / 可用 X」；
   (d) 行操作收进「⋮」（详情 / 对账 / 编辑 / 归档 / 删除 / 上移 / 下移），
       整格长按仍可拖动排序、TalkBack 上移下移兜底保留；
   (e) 新建页为近全屏蓝底 TopBar + 图标名称小卡 + 底部大保存，字段与保存逻辑零回归；
   (f) 模板 sheet 按资产组 / 信用负债组 2 列展示、4~5 字模板名完整可见，
       点选自动填名称与类型、可再填卡号后四位、「自定义名称」入口保留；
   (g) 真机：360dp 窄屏不溢出、拖拽与菜单不误触、覆盖安装数据不丢。
5. **被否决方案**：①照抄一羽单一净资产总数（违反不跨币种汇总）；
   ②照抄一羽分组白卡 / 卡片阴影（违反资产行纯行规范）；
   ③照抄 IconFont 在线 PNG（需 `project.md` 显式授权联网，本批不申请）；
   ④新增备注 / 隐藏账户 / 默认使用字段（属功能新增，非 UI 优化，需单独决策）；
   ⑤新增 Navigation 路由（改动面外溢，用 `Dialog` 实现全屏视觉即可）。
