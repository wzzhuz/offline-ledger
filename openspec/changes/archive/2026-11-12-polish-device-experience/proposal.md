# polish-device-experience · 真机体验打磨

## 为什么

使用者已把 `43446433266` 的 R8 release 包装到手机上完成第一轮体验，提交 7 条反馈。
这是项目**第一次真机反馈**，性质与前几个阶段不同：前六个阶段是「按规格把功能做出来」，
本 change 是「按真实手感把做错的地方改对」。其中 2 条是我在 v2 设计期按错误假设
写死的默认值（香港 / HKD），不是小瑕疵。

## 五项对齐结论

### 1. 要解决什么问题

把「能装、能记」推进到「愿意长期用」：默认币种与所在地对齐、预置账户能设期初余额、
日期能一次选到任意一天、记录能看清钱付给谁、记一页不用上滑、加号不挡列表、
模板分类不再张冠李戴。

### 2. 改什么 / 不改什么

**改**：
- 全局默认币种 `CNY`、默认时区 `Asia/Shanghai`；设置页新增「默认币种」下拉与
  「把现有账户与流水统一改为该币种」按钮
- 资产页新增账户编辑：期初余额、币种、名称、信用额度、计入净资产
- `records` / `trash` / 模板 / 周期规则 / 备份 DTO / CSV 增加 `counterparty` 自由文本字段
- 记一笔：紧凑布局、纯数字键盘、日历选择器、收款方输入与常用收款方补全
- 底部 `+` 从悬浮 FAB 改为底栏内嵌按钮（仍是 4 Tab），不再遮挡列表
- 模板管理：分类按收支类型过滤、按一级分组、列表行显示分类
- 稳定版前重置 `AppDatabase version = 1`、清空迁移注册
- `project.md` / 2 份 MODIFIED / 新增 Requirement 与单测

**不改**：金额铁律（`Long` 分）、统计口径唯一出口、两级分类上限、4 Tab 格数、
复式记账（收款方 MUST NOT 建成账户）、跨币种混算与汇率、小组件、通知、
加密备份能力、Manifest 权限（`INTERNET` 仍不声明）、`release.yml`。

### 3. 关键约束

- **隐私边界按使用者澄清**：真正不可接受的是「数据存在厂商服务器」；
  本地明文 CSV 由使用者掌控，不构成违规。App 仍 MUST NOT 声明 `INTERNET`、
  MUST NOT 有网络上传。
- **收款方是标签不是账户**：`counterparty: String`，无外键、无独立表、无复式分录；
  仅用于明细展示、常用值补全、CSV 与备份往返。
- **默认可配、已有数据不自动改**：改默认币种只影响新建账户；
  批量统一币种是使用者显式点按钮才执行，且同步更新流水与回收站的冗余币种标签。
- **账户编辑改期初余额 MUST 触发余额重算**，且走既有 `withTransaction` 写路径。
- **稳定版前不保留迁移**：`version = 1`、`Migrations.ALL = emptyArray()`；
  已装机包必须**卸载重装**（先用 CSV 导出测试数据）。这是使用者明确授权的路径，
  CI 编译通过不代表可覆盖升级。
- 六个静态检查全 PASS；单次 commit 推送；Python 拼 Kotlin 后必跑
  `check_kotlin_strings.py`；沙盒无 SDK，编译与单测由 Actions 验证。

### 4. 验收标准

1. CI 全绿且 Actions 能查到该次运行，六个静态检查仍 PASS
2. **GIVEN** 全新安装 **WHEN** 打开资产页 **THEN** 四个预置账户币种为 CNY，
   设置页显示默认币种 CNY
3. **GIVEN** 编辑预置「微信零钱」输入期初余额 1000.00 **THEN** 余额变 100000 分，
   且重算后净资产一致
4. **GIVEN** 记一笔点日期 **THEN** 弹出日历可选任意一天，不再只能一天天挪
5. **GIVEN** 记一笔首屏 **THEN** 备注与收款方输入框无需上滑即可见，
   键盘只有 `0-9 . ⌫ C`，无 `+ - × ÷ ( ) =`
6. **GIVEN** 底部 `+` **THEN** 位于底栏内部，明细列表末尾不被遮挡
7. **GIVEN** 选「支出」建模板 **THEN** 分类下拉只出现支出分类且按一级分组；
   模板列表行显示「一级 / 二级」
8. **GIVEN** 记一笔填收款方「盒马」 **THEN** 明细行显示、CSV 导出有 `counterparty` 列、
   加密备份往返后仍保留
9. **GIVEN** 归档 **WHEN** 校验 specs **THEN** 2 份 MODIFIED 按标题替换、
   `project.md` 覆盖声明已落地、无「悬浮 FAB / 计算器键盘 / HKD 默认」的现行要求
10. 远端 sha 校验 PASS、无 token 明文

### 5. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 不建 change 直接改 UI | 7 条反馈含表结构与默认值决策，改动会失溯源 |
| 收款方建成账户 / 引入复式记账 | 使用者明确「只是不用那么严格，也不需要搞成账户」；复式会推翻整个单式模型 |
| 加 `counterparty` 但写显式 Migration 保留升级 | 使用者明确稳定版前不考虑升级迁移；多一段迁移多一处运行时风险 |
| 改默认币种时自动把已录流水全改 | 会改动使用者正在核对的测试数据，必须显式点按钮 |
| 键盘保留 `+` 方便合并算账 | 使用者本轮明确「输入金额都不需要加减乘除括号」，按最新意见收敛 |
| 把 `+` 做成第 5 个 Tab 或直接删掉 | 违反 spec 的「恰好 4 Tab + 中央记账入口」 |
| 逐条 MODIFIED 改十几处 HKD / 计算器 / FAB 历史文本 | 改动面大、易漏、抹掉历史决策；改用 2 份关键 MODIFIED + `project.md` 覆盖声明 |
| 把设置项塞进 Room 或备份 DTO | 偏好不进账本，沿用 SharedPreferences |
| 顺手做 v1.1 待决策项 | 本 change 只处理真机反馈，范围不蔓延 |

完整取舍与查证结论见 `design.md`。

## 第 3 批追加范围（使用者第二轮装机后追加 6 条）

| # | 反馈 | 本批落地 |
|---|---|---|
| 1 | 模板金额必填不合理；模板应是「选了自动填充、空的再填、还能自由改」 | 模板改草稿语义：金额可空，选中后填分类/账户/类型/备注/交易对方/不计入收支，日期用现在，全部字段可改；未填金额 MUST NOT 直接生成流水 |
| 2 | 模板无编辑删除；类型与选中态没有高亮 | 模板 CRUD（含删除二次确认）、类型 segment 与记一笔中模板 chip 高亮、列表行显示类型与分类路径 |
| 3 | 账户类型选错不能改、不能删除重建、归档无入口、排序没做 | 账户编辑加类型修正、无流水可物理删除、已归档可查看与恢复、上移/下移排序（顺序同步到记一笔常用账户） |
| 4 | 趋势图与收入共用最大值看不清、横轴只 3 个标签、没有数值、建议放大横屏、竖轴显示具体值 | 单线按该系列自身最大值缩放、竖轴 5 个元刻度、点击仍可取具体金额、新增「⛶ 横屏放大」全屏 Activity（横轴全标签 + 双指缩放） |
| 6 | 分类管理没有删除、二级父级只看到部分一级、不能拖动选择 | 删除（有流水自动降级归档）+ 恢复、一级/二级上移下移、父级改「搜索 + 可滚动全量列表」 |
| 7 | 账户详情名称栏与列表不一致 | 详情标题改用资产页列表实时传入的名称，移除详情里重复的改名输入框，账户编辑收敛到资产页唯一入口 |

**不改**：表结构、备份格式、`schemaVersion`、4 Tab 导航、记一笔/明细/资产/统计既有行为、
统计口径唯一出口、金额铁律、不混算、`release.yml`、Manifest 权限（仍不声明 `INTERNET`）、
历史快照。`AppDatabase` 仍 `version = 1`，按使用者「稳定版前不考虑升级迁移」的约束，
本批**不新增 Migration、不新增任何 Gradle 依赖**。

三项拍板均按推荐 A：横屏全屏页、账户「有流水只归档 / 无流水可删」、并入本 change 一次出包。
