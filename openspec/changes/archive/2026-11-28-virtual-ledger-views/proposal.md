# 虚拟账本（视图级专项台账）

## Why

使用者提出结婚礼金场景：收的礼金属人情往来、最后都要还，不想记成收入让月度
收入虚高；希望有个「类似多账本」的独立空间集中记录与查看，入口像一羽左上角
账本切换，设置页可管理。

前一轮已确认：礼金不是「项目」，是**往来 / 人情债**——双向、无期限、按「人」
而不是按「项目」组织。市面上多账本是互斥的项目容器，且「切换后新账单自动进
当前账本」会与本项目「分享 → 0 次确认自动落库」组合成静默记错账。独立 app
则会让资金真实进入主账本账户却不在主账本记账，撞铁律 2。

## What Changes

- 新增「虚拟账本」概念：统一前缀标签 `台账:<名称>` + 独立只读视图，**不是账本维度**。
- 主界面 4 Tab 顶部新增切换器（仅主 Tab 显示），设置页新增管理与入口。
- 新增台账页：按 `counterparty` 分组显示 收 / 还 / 待还，列出本台账流水，
  提供「记收礼 / 记还礼」两个带预填的录入入口。
- 记一笔新增三个可选预填参数（类型 / 标签 / 不计入），仅台账录入使用。
- 主账本明细默认排除台账标签记录；显式按标签筛选时恢复显示。
- 静态检查新增 `check_virtual_books.py` 并注册进 build.yml。

## 明确不做

- 不加 `bookId`、不升 Room version、不改 12 张 Entity、不改备份 DTO、不改 CSV 格式。
- 切换器 MUST NOT 携带录入归属；记一笔 FAB 与自动记账 MUST 永远落主账本。
- 不做成员 / 共享账套 / 云同步 / 账号体系（`project.md` 永久不做条目，本批仅补界定句）。
- 不用 SETTLEMENT 配对、不建虚拟负债账户、不做跨启动记忆当前账本。
- 不补 CSV `excludeFromStats` 列（使用者明确 CSV 不会是备份主力）。

## Capabilities

- `reporting-ui`：虚拟账本切换器、台账页、设置页、明细排除口径。
- `ledger-transactions`：台账聚合 SQL 口径与录入预填。
