# 第 78–79 批：视觉规范适配（深色主题 / 金额等宽 / 设计 token / 真机反馈修复）

## 为什么改

对一份「现代极简视觉规范」做仓库适配审阅后的落地批。原规范方向成立（去线留白、
卡片化、语义色、`tnum`、层级 token），但直接照搬会与本项目 77 批真机沉淀的基线
正面冲突：全站删分割线违反「明细页固定四列网格 + 细分割线」、
明细 / 记一笔 / 资产列表卡片化违反既有 Requirement、
彩色图标扩范围与 `Icons.Rounded` 会撤销第 55/56/68 批逐次放行的口径。
故只取其中三项真缺口 + 一个已登记的隐患。

第 79 批为真机反馈修复：v0.2.57 装机后反馈
①「统计页浅色模式下卡片之间分界不明显了」
②「蓝底顶栏太蓝了，跟整个 app 风格不搭，太突兀」。
两条根因都在第 78 批自身，见 `design.md`。

## 做什么

- 新增深色模式（跟随系统，静态深板，深色语义色），动态浅色收口为「只借强调色、中性槽位固定」
- 金额文本统一 `tnum` 等宽数字与四级排版（32sp / 16sp / 15sp / 12sp）
- 新增 `LedgerDesignTokens.kt`：圆角 / 间距 / 字级 token
- `LedgerColors` 升为可观察调色板，拆出 `Background` / `CardSurface` / `OnSurface` 三语义
- `CategoryHeaderBlue` 改读可观察主色，收敛第 77 批登记的两套蓝
- 6 处整块蓝底顶栏与资产页身份区改中性卡片 + `OnSurface` 文字
- 统计卡容器固定纯白、间距回 16dp
- 归档时把 delta 合并回 `reporting-ui` / `category-stats` 两个 spec（ADDED 3 / MODIFIED 7）

## 不做什么

- 不删除任何 `ListDivider` / `FormDivider`，不改明细页、记一笔、资产列表的纯行网格
- 不把明细 / 记一笔 / 资产列表卡片化，不新增阴影 / 描边
- 不扩大彩色图标范围，不引入 `Icons.Rounded.*` 或 `material-icons-extended`
- 不用 `CompositionLocal` 重写 237 处语义色引用
- 不加缩放动画（Ripple 已由 M3 默认提供，项目在拖拽手势上有历史坑）
- 不改 4 Tab 导航、不改记一笔首屏分层、不改聚合 SQL / 数据口径
- 零改表（`AppDatabase.version = 8` 不动）、零新增 Gradle 依赖、零 permission 变化

## 对齐结论（五项）

| # | 项 | 结论 |
|---|---|---|
| 1 | 要解决什么问题 | 界面观感不齐整：缺深色模式、金额列易跳动、卡片边界模糊、蓝底顶栏突兀；同时要避免照搬通用视觉规范推翻已验证的项目基线 |
| 2 | 改什么 / 不改什么 | 见上两节。范围锁定在 `ui/theme/`、统计 / 明细 / 交易详情的金额样式、6 处顶栏与身份区、表面色引用点；布局 / 手势 / 数据层一律不动 |
| 3 | 关键约束 | 三条铁律（数据是你的 / 账要算得准 / 记账不能变慢）；`reporting-ui` 既有 Requirement 不得出现两条相反要求；零改表、零新增依赖、零 `INTERNET`；`dynamicColor = false` 回退路径保留；沙盒不编译 APK，走 GitHub Actions |
| 4 | 验收标准 | 12 个静态检查全 PASS + 单测 + Debug + Release lintVital 全绿；v0.2.57 / v0.2.58 两个 Release 包出包成功；真机逐页确认浅色卡片边界、深色无残留白块、`tnum` 对齐、顶栏风格一致、覆盖安装数据不丢 |
| 5 | 被否决的方案及原因 | 全站卡片化 / 删分割线（违反既有 spec 且是项目已证伪路径）；`CompositionLocal` 重写语义色（237 处引用含非 Composable 上下文，成本高且会破坏反转开关）；系统动态深色（primary 为浅色调，小面积主色上的白图标失去对比）；固定 12dp 卡片间距（真机反馈边界糊）；详见 `design.md` |
