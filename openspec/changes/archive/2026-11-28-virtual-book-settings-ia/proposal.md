# 第 95 批：虚拟账本设置页 IA 整理 + 设置主菜单功能分组

## 用户反馈（v0.2.73）

1. 虚拟账本「新建」和「已建列表」挤在一页，混杂 → 是否拆开
2. 没有删除功能；配置 / 重命名 / 归档 / 上移下移占了两行 → 是否参考账户列表收进右侧三个点
3. 设置主菜单规划感觉乱 → 是否按功能合理调整

## 一处清点纠正（如实登记）

上一轮影响分析里我写「设置主菜单是一条大 `LazyColumn` 全平铺」——**说错了**。
核查 `SettingsScreen.kt` 发现第 4/15 批早就做成了 8 张 `SettingGroupCard`，
且有一处 `SectionTitle("关于")`。真正的问题是：**只有「关于」有标题，其余 8 张
卡片无小节标题、顺序按频率交错**（账本 / 标签 / 虚拟账本 / 数据与备份 / 规则 /
自动记账 / 偏好 / 安全），功能上跳跃，观感乱。

所以本批只做「补 4 个分组小节标题 + 重排 item 顺序」，不改 route、不增删条目、
不动二级页。又是一次 §7.51「借鉴/外推前先清点本仓已有什么」。

## 要解决什么

| # | 问题 | 处理 |
|---|---|---|
| 1 | 新建表单与列表混屏 | 新建拆到独立 `VirtualBookCreateScreen`，列表页右上角「+」进入 |
| 2 | 操作占两行、无删除 | 七项操作收进右侧「⋮」，与 `AssetsScreen` 账户卡同款；`VirtualBookStore.remove()` 只删视图定义 |
| 3 | 设置主菜单乱 | 按 4 组补小节标题并重排：账本与分类 / 数据与自动记账 / 偏好与安全 / 关于 |

## 删除边界（关键）

**只删视图定义，MUST NOT 删流水。** 流水仍带 `台账:<name>` 标签躺在 `records`
表，主账本明细照常可见、余额不变；`tagFor(name)` 由名字稳定派生，新建同名
视图即可重新聚合。确认弹窗必须把这两句写清楚，否则用户会误以为「删了=钱没了」。

## 用户拍板

1. **A** 独立「新建虚拟账本」页 + 列表页右上角「+」
2. **A** 只删视图定义、保留流水、弹窗明说可同名重建
3. **按推荐 4 组**（账本与分类 / 账户与资产 / 数据与安全 / 偏好与关于）

第 3 项按实际条目落地时微调为 **账本与分类 / 数据与自动记账 / 偏好与安全 /
关于**：仓库里没有独立的「账户管理」设置入口（账户在资产 Tab 里管），
硬凑第二组会是空组；自动记账是独立 Activity 入口，与数据备份同属「数据进出」。
8 张卡片一条不少。

## 不改什么

- 表结构（Room version 仍 9）、备份 DTO、CSV 格式、预置分类清单、12 张 Entity
- 4 Tab 骨架、统计模块、自动记账落库位置、虚拟账本定义存储口径
- 场景模板逻辑（第 94 批）、切换不带录入归属、自动记账永远落主账本
- 任何 route 字符串、任何设置二级页、`TextIntakeActivity` 内部入口行为
