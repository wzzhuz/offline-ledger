# CSV 明文导出与账单导入（阶段 6c-2）

> **本文件是 change 的上下文入口。** 新会话只读这一份，就能还原本次改动全貌。

## 为什么改

**背景**：

- 使用者最初规格书里就写了「导出标准 CSV 表格文件（方便用电脑 Excel 打开查看）」，
  但阶段 5 当时以「CSV 是明文导出，与导出文件默认加密张力最大」为由判 v1 不做。
  **6c-1 使用者正式推翻了这个理由**：

  > 「导出明文是可接受的，数据掌控在自己手里就可以，
  > 不可接受的是市场上 app 将数据保存在他们服务器上。」

  现在隐私边界明确为「账本数据 MUST NOT 上传第三方服务器 / 托管给厂商」，
  本地文件是否加密、放在哪里由用户决定。CSV 不再需要隐私评审，
  只差按闸门显式放行
- 6c-2 之前还遗留两件 v1.1 清单项：账单导入、明细页与统计页币种口径一致性
  （6c-1 落地时明细页仍显示「全部币种」，统计页已按币种筛选）
- **使用者本轮明确新约束**（条件性暂缓，已写进 `project.md`「稳定版前的版本策略」）：

  > 「暂时不用考虑升级场景，在出一个满意的稳定版本之前不会立即使用，
  > 只会使用测试数据，数据结构完全不需要考虑升级迁移，
  > 除非我说明需要考虑升级迁移。」

  因此本批**不新增 Migration、不改 `AppDatabase version`、不改备份 `schemaVersion`**，
  并把 `check_transaction_annotations.py` 的迁移/版本门禁降级为记录性提示。
  **任何阶段 MUST NOT 再以「会破坏升级 / 要写 Migration / 旧备份读不了」否决结构调整**

**设置页现状**（写码前实际读了）：仍写着
「v1 不提供 CSV 导出（明文文件，列在 v1.1 清单）」，本批一并改掉。

## 做什么

1. **闸门**：`project.md` 把 CSV 导出、账单导入、明细/统计币种一致性
   三项标为「6c-2 本批实现」
2. **1 份 MODIFIED**：`ledger-transactions`「显式迁移且 seed 覆盖升级场景」
   改为「稳定版前的版本策略」长期表述，写清恢复条件；
   其余十几条历史 Requirement 保留不删，由 `project.md` 暂缓清单统一声明
3. **CSV 明文导出**（`CsvCodec.export`，纯 JVM）：
   UTF-8 with BOM、表头固定 8 列、金额以元两位小数、带 `currencyCode`；
   SAF `CreateDocument("text/csv")` 写出，**不申请任何存储或网络权限**
4. **账单导入**（`CsvCodec.parseImport`，纯 JVM）：
   自定义极简 CSV/TSV 模板（与导出互为镜像），解析 → 全量校验 →
   展示「将写入 N 条」二次确认 → **单事务批量写入** → 末尾重算；
   任一行非法 MUST 整体回滚；去重按「账户 + 金额 + 日期 + 备注」查询，不加新字段
5. **明细页币种筛选**：`pagedFiltered` / 日合计加可选 `currencyCode` 参数
   （`:currencyCode IS NULL OR ...` 短路，null 时行为不变）；
   `RecordFilter` 加字段、筛选面板加币种选择、默认「全部币种」；
   与统计页同币种同月份合计一致
6. **门禁降级**：`check_transaction_annotations.py` 把
   `version` / `Migrations.ALL` / `DEFAULT` 检查改为**记录性提示不失败**，
   保留「30 个写方法在事务内」与「破坏性迁移禁令」的硬检查
7. 纯 JVM 单测覆盖 CSV 往返、BOM、金额两位小数、非法行整体回滚、
   去重、明细筛选 revision、门禁降级；六检查全过

## 不做什么

- ❌ **不把已加密的 JSON 备份降级成明文**（「明文可接受」≠ 拆掉已有能力）
- ❌ **不做「默认关闭 / 强制二次确认 / 明文文件勿放公共目录」这类
  以明文风险为前提的拦截**（理由已被推翻）；导出入口本身仍给一次常规确认
- ❌ **不新增 Migration、不改 `AppDatabase version`、不改备份 `schemaVersion`**
  （稳定版前条件性暂缓）
- ❌ **不适配支付宝 / 微信 / 银行私有账单格式**（字段随版本变、含无关列、
  编码不可控；采用自定义极简模板）
- ❌ 不做自动记账、跨币种混算与汇率、小组件、通知栏磁贴（永久不做 / 待决策）
- ❌ 不逐条 MODIFIED 十几份历史 Requirement（规格腐烂风险）
- ❌ 不改 4 Tab 导航、既有 ForCurrency 查询、资产 / 对账 / 预算 / 报表既有行为、
  Manifest 权限、`release.yml`、`my-app-workflow`、历史快照
- ❌ 不引入任何新 Gradle 依赖、不申请任何新权限、不新增网络行为

## 对齐结论

> 阶段 0 在对话里产出，五项齐全才进入写作。
> 使用者回复「按推荐来」即确认 A + A′ + A。

1. **要解决什么问题**
   收掉 v1.1 最后三件：CSV 明文导出（用户最初「方便 Excel 打开」的原话）、
   账单导入（减少手工补录）、明细与统计币种口径一致性；
   同时按新约束放宽迁移门禁，让后续阶段不再为升级背负担。

2. **范围边界**
   - 改：闸门 / 1 份 MODIFIED / CSV 编解码 / SAF 导出与导入 / 导入事务与去重 /
     明细筛选与日合计 / 设置页文案与入口 / 筛选面板 / 门禁脚本 / 单测
   - 不改：6c-1 与更早的全部既有行为、4 Tab 结构、表结构、备份格式、
     加密 JSON 备份、Manifest 权限、构建链、历史快照

3. **关键约束**
   **隐私边界**：CSV 是明文文件但只写入用户通过 SAF 自选的位置；
   App 仍 MUST NOT 声明 `INTERNET`、MUST NOT 有网络上传，
   `check_manifest_privacy.py` 继续 PASS。明文不构成违规。
   **CSV 格式**：UTF-8 with BOM、金额以元两位小数、带 `currencyCode` 列、
   日期 `YYYY-MM-DD`；`BigDecimal` 只在展示层转换，`Long` 分不变。
   **导入**：解析 MUST 纯 JVM 可单测；校验失败 MUST 整体回滚，
   MUST NOT 留半套数据；去重按「账户 + 金额 + 日期 + 备注」查询，
   优先不加新字段；导入流水 MUST 走既有 `insertRecord` 同一事务 +
   末尾重算 + 币种继承，不新开写余额路径；MUST 只接受 EXPENSE / INCOME。
   **新约束落地**：6c-2 不新增 Migration、不改 `AppDatabase version`、
   不改备份 `schemaVersion`；实现中若要加字段可直接改 Entity 并重置 version，
   MUST NOT 以升级兼容为由否决。门禁降级但写方法事务与破坏性迁移禁令保留。
   `check_stat_rules.py` 与金额铁律不变；零新增依赖 / 权限 / 网络行为；
   六个静态检查全过；推送单次 commit；沙盒无 SDK，编译与单测由 Actions 验证。
   **真机验证继续推迟**：清单按新约束移除「三段 Migration 覆盖升级」后，
   其余各项全部保持未验证，不得改写成「已通过」。

4. **验收标准**（可测）
   - **GIVEN** HKD 3850 分与 CNY 2000 分支出 **WHEN** 导出 CSV **THEN**
     两行金额为 38.50 / 20.00、`currencyCode` 正确、Excel 打开不乱码
   - **GIVEN** 导入一份含 1 行非法金额的 CSV **THEN** 整体回滚、
     账本零变化、报告指出第几行
   - **GIVEN** 导入 10 行合法 CSV **THEN** 10 条流水走同一事务、
     余额重算后各账户一致、币种从账户继承
   - **GIVEN** 明细页选 HKD **THEN** 列表与日合计只含 HKD，
     且与统计页同月份 HKD 合计一致
   - **GIVEN** 故意删掉 `MIGRATION_3_4` **WHEN** 跑静态检查 **THEN**
     只提示不失败；删掉某个写方法的事务包裹仍失败
   - **GIVEN** 归档 **WHEN** 校验 specs **THEN** 1 份 MODIFIED 按标题替换、
     无与 `project.md`「稳定版前的版本策略」相反的要求
   - **GIVEN** CI 跑完 **THEN** 六个静态检查、单测、debug/release 全绿

5. **被否决的方案**
   一句话结论：**所有「仍拿明文风险拦 CSV / 把 JSON 降级成明文 /
   导入绕过既有事务另开写余额路径 / 解析失败部分写入 /
   逐条 MODIFIED 十几份历史要求 / 适配某一家私有账单格式 /
   因『要写 Migration』而放弃去重字段 / 顺手做自动记账与跨币种混算」
   的方案均被否决**，采用「闸门放行 + 1 份 MODIFIED + 纯 JVM CSV 编解码 +
   SAF 明文导出 + 事务化批量导入 + 明细可选币种筛选 + 门禁记录性降级」。
   完整表格见 `design.md`「考虑过的其他方案」。
