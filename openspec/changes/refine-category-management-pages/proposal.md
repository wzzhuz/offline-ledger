# 分类管理三页借鉴一羽记账的布局与交互（列表 / 排序 / 分类选择）

> 本文件是 change 的上下文入口。新会话只读这一份文件，

## 日期

2026-11-23

## 为什么改

使用者给出三张真机对照图：图 1 是本 App 当前「分类管理」页，
图 2 / 图 3 是一羽记账的「分类管理」与「分类排序」页。原话：

> 「一级横排图标+二级彩色网格图标不借鉴这一条不太认同。图一是我们app效果，
> 图二和图三是一羽的，我们效果差别人一大截。留白大应该是前期布局没考虑好」

核查后确认使用者的判断成立，需要撤回本会话早先的一处错误外推：

- 活文档 §7.3 记的是「BeeCount 的 `_CategoryGridView` **网格卡片**在
  10 一级 + 20 二级时会回到留白大」，针对的是卡片堆叠 + 内边距 + 阴影，
  **不是**一羽这种「固定列数、等宽图标格子」。
- 本 App 第 16 批是主动把留白留在右侧的（活文档 §7.6 自述
  「短名行的剩余留白 MUST 固定留在右侧」）；`WrapRow` 按文本收缩，
  再叠「（停用）」后缀，行尾碎留白越积越多。一羽把同样的留白
  **均匀切成 gutter**，观感上就不叫空了。
- 差距是六处叠加，不只是有没有图标：白底顶栏无层级 vs 蓝底 + 收支 Tab
  坐进标题栏；一级纯文字 + `≡ › ⋮` 三连 vs 圆图标 + 名称 + 数字角标 + 单 `⋮`；
  长短不一的自适应 chips vs 5 列等宽图标格；顶部一整段灰字常驻占首屏 vs 无常驻说明；
  无拇指区主操作 vs 胶囊容器 + 蓝色大 `+`；停用态拼进名字撑破 chip vs 不占文本。

数据侧复核（`assets/default_categories.json` version 4）：一级 15 / 二级 91，
启用 47 / 停用 59；**单个父级最多 11 个二级**（居住 11、餐饮 10、养车 9），
5 列即 3 行，完全放得下，不会出现 §7.3 担心的规模爆炸。最长名 7 字
「赡养·代缴水电」，需要固定格高 + 单行省略。
106 行的 `iconName` **全为空**、`colorHex` 恒为 `#888888`，
上彩色图标不是「读出来就行」，必须补一份图标数据。

## 做什么

1. **列表页借一羽布局**：蓝底 TopBar（返回 / 标题 / 右上「排序」+ ⋮），
   支出 / 收入 Tab 坐进标题栏下部；一级仍竖排 `LazyColumn` 行，
   行内为「彩色图标 + 名称 + 二级数角标 + 单 ⋮ 菜单」，
   `≡ / ›` 收进菜单；展开区二级改为 **5 列等宽彩色图标网格**，
   末位固定「添加子类」格；停用改为小角标，MUST NOT 再拼进名称；
   顶部说明灰字收进 ⋮ 的「使用说明」；底部胶囊容器放
   「已归档（N）/ 停用项管理」两个入口 + 蓝色大 `+` FAB 作主新增。
2. **新增独立「分类排序」页**：一级横排 5 列图标，选中一级的二级收进
   圆角白卡且用**灰阶单色**（一羽自己排序页就降饱和）；
   底部提示「长按拖动一级，点按拖动二级」+「保存」；
   **临时顺序与已落库 `sortOrder` 彻底分离**，保存时一次性写回，
   作用域仍是 `(type, level, parentId)` 三元组；放弃/返回 MUST NOT 静默写库。
   排序页内二级临时排成**一维列表**以适配 `reorderable` 的一维模型；
   列表页仍是等宽网格。
3. **新增「分类选择」页**（借一羽「添加二级分类」页版式）：
   左侧分组导航 + 右侧等宽网格 + 顶部搜索 + 父级预填 + 「继续添加」，
   用于新增二级时选父级、以及批量挑选停用扩展项。
   **只借版式，不改语义**：不从预设分类库里「挑一个分类加进来」。
4. **放开彩色图标，但限定页面**：分类管理三页（列表 / 排序 / 选择）
   SHALL 用本地图标目录呈现彩色具象图标；**记一笔、明细、统计页保持
   中性圆 + 中文首字不动**。图标资源 MUST NOT 复制一羽的视觉资产，
   SHALL 采用自有或可商用矢量集，许可证与传递依赖审计写入 `design.md`。
5. 同步修订 3 条已写死的 Requirement（按标题整块 MODIFIED，不留矛盾文本）：
   - `category-stats`「分类图标不做字符串映射」
   - `category-stats`「分类管理全量父级与排序」
   - `reporting-ui`「管理类页面入口固定且列表与编辑分离」
   并修订活文档 §2.6 / §7.3 中「中性单色圆 / 彩色图标目录一律不进清单」的全局表述，
   明确其适用范围收窄为记一笔 / 明细 / 统计页。

## 不做什么

- ❌ **不动记一笔页、明细页、统计页**的分类标识（中性圆 + 首字照旧）。
  使用者的来由是「原来记一笔页面有图标显示效果差，现在只看分类管理相关页面」。
- ❌ 不动两级数据模型、`AppDatabase.version`（仍 5）、`Migrations.ALL`（仍空）、
  DAO / SQL 出口、统计口径与环形图扇区配色：图标配色由图标目录常量提供，
  **MUST NOT 改写 `colorHex`**（该字段参与 `ChartData` 扇区取色）。
- ❌ 不动 `assets/default_categories.json` 的 ID 规则、启用/停用语义、
  备份整表替换、CSV / Firefly 按名称匹配路径。
- ❌ 不做「系统分类 / 分类扩展包」一键安装：底部胶囊只借位，
  换成已有的「已归档」「停用项管理」，不碰预置清单闸门。
- ❌ 一级列表**不横排**：横排只出现在排序页；列表页保持竖排 `LazyColumn`
  （第 12 批骨架），避免一屏塞不下 15 个一级。
- ❌ 不删除上移 / 下移（TalkBack 无障碍兜底）、不删改名 / 删除 / 看流水 / 停用五项操作。
- ❌ 不引入三级分类、账号体系、云同步、埋点、崩溃上报、远程配置 SDK。
- ❌ 不新增第三方 UI 库：等宽网格用稳定 `Row + weight(1f)`，拖拽仍用
  `sh.calvin.reorderable:3.1.0`，MUST NOT 用 `LazyVerticalGrid` 嵌进
  `LazyColumn` 的 `item {}`（同方向嵌套滚动 + 高度不确定），
  MUST NOT 用 `@OptIn(ExperimentalLayoutApi)` 的 `FlowRow`（T12）。

## 对齐结论

> 阶段 0 的产出。五项齐全才进入写作。
> 新会话只读这一节，即可还原本次改动的完整上下文，无需重新讨论。

1. **要解决什么问题**
   分类管理三页观感与操作路径明显弱于一羽记账，用其布局与交互逻辑优化；
   并纠正「等宽图标网格必然留白大」这一错误外推——真正的问题是
   前期 `WrapRow` 自适应 + 行尾留白 + 停用后缀拼进名称，不是网格本身。

2. **范围边界**
   - 改：列表页布局（含二级等宽彩色图标网格）、新增独立排序页、
     新增分类选择页、补图标数据、修订 3 条 Requirement + 活文档 §2.6/§7.3。
   - 不改：记一笔 / 明细 / 统计页分类标识、两级模型、表结构、
     统计口径、清单 ID 规则、备份整表替换、5 个进行中 change 的 delta。
   - 详见上文「做什么」「不做什么」两节。

3. **关键约束**
   - 零改表 → v0.2.35 直接覆盖安装，不需要导出 / 卸载 / 导入。
   - 排序作用域固定 `(type, level, parentId)` 三元组，
     继续共用 `reorderable:3.1.0` + `rememberKeyedReorder`，
     松手 / 保存时一次性写 `sortOrder`；上移 / 下移保留为无障碍兜底。
   - 分类管理 MUST 保持「顶部固定入口 + 惰性列表 + 编辑独立视图」骨架
     与 `ListDivider()` 单一来源；可点区 ≥ 40dp。
   - 图标 MUST NOT 用 `iconName` 字符串在运行时反射 / 查表映射
     （T14 整份编译失败）；缺图标 MUST 回退中性圆 + 首字。
   - 图标资源 MUST NOT 复制第三方视觉资产；许可证与传递依赖审计须落盘。
   - 活文档 §1：CI 全绿不替代真机观感 / 性能 / 弹窗验证，
     本批 MUST 显式列出真机待验项并继承 §8 既有清单。

4. **验收标准**（可测）
   > 按上一轮约定「按你拟的」由本 change 拟一版，写在 proposal 里供使用者确认，
   > 不是使用者逐字给出；确认时可直接改 / 砍 / 补。

   - **GIVEN** 支出一级「餐饮」下有 11 个二级（含停用项与 7 字长名）
     **WHEN** 展开「餐饮」
     **THEN** 二级呈 5 列等宽彩色图标网格，长名单行省略、
     停用为小角标、末位为「添加子类」，且行尾无碎留白、无卡片阴影
   - **GIVEN** 打开分类管理页
     **WHEN** 查看首屏
     **THEN** 蓝底 TopBar + 收支 Tab 可见、无常驻说明灰字、
     底部大 `+` FAB 固定可见、一级行右侧只保留一个 ⋮ 菜单
   - **GIVEN** 进入分类排序页并拖动了一级与二级，未点保存
     **WHEN** 按返回 / 放弃
     **THEN** 库内 `sortOrder` 零变化，重进列表页顺序不变
   - **GIVEN** 在排序页调整后点「保存」
     **WHEN** 写入完成并重进页面
     **THEN** 一级只在支出一级之间换位、二级只在所属父级内换位，
     收入分类与另一父级的二级顺序完全不变
   - **GIVEN** 从「餐饮」行点「添加子类」
     **WHEN** 打开分类选择页
     **THEN** 父级「餐饮」与收支类型已预填，顶部搜索可用，
     「继续添加」可连续建二级且每次写库后不丢已填内容
   - **GIVEN** 打开记一笔 / 明细 / 统计页
     **WHEN** 查看分类标识
     **THEN** 仍是中性圆 + 中文首字，无本批彩色图标
   - **GIVEN** 某个分类在图标目录中缺项
     **WHEN** 渲染三页网格
     **THEN** 回退中性圆 + 首字，不崩溃、不整份编译失败
   - **GIVEN** 3 条 MODIFIED 与 4 条 ADDED 写完
     **WHEN** 跑归档校验
     **THEN** 无重复 Requirement 标题、每条 ≥1 个 Scenario、
     含 RFC2119 关键词、MODIFIED 按标题整块替换且无矛盾文本

5. **被否决的方案**
   见 `design.md`「考虑过的其他方案」表。一句话结论：
   **撤回「不借鉴网格」这一条**；仍否决「一级列表也横排」、
   「彩色图标目录整份进记一笔 / 明细页」、「扩展包一键装」、
   「二维网格上硬做拖拽」、「改 `colorHex` 给图标上色」。
