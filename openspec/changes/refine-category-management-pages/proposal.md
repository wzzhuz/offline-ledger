## 日期

2026-11-23

## 为什么改

使用者给出三张真机对照图：图 1 是本 App 当前「分类管理」页，
图 2 / 图 3 是一羽记账的「分类管理」与「分类排序」页。原话：

> 「一级横排图标+二级彩色网格图标不借鉴这一条不太认同。图一是我们app效果，
> 图二和图三是一羽的，我们效果差别人一大截。留白大应该是前期布局没考虑好」

核查后确认使用者的判断成立，需要撤回本会话早先的一处错误外推：

- 活文档 §7.3 记的是「BeeCount 的 `_CategoryGridView` **网格卡片**在
  10 一级 + 20 二级时会回到留白大」，针对的是卡片堆叠 + 内边距 + 阴影，
  **不是**一羽这种「固定列数、等宽图标格子」。
- 本 App 第 16 批是主动把留白留在右侧的（活文档 §7.6 自述
  「短名行的剩余留白 MUST 固定留在右侧」）；`WrapRow` 按文本收缩，
  再叠「（停用）」后缀，行尾碎留白越积越多。一羽把同样的留白
  **均匀切成 gutter**，观感上就不叫空了。
- 差距是六处叠加，不只是有没有图标：白底顶栏无层级 vs 蓝底 + 收支 Tab
  坐进标题栏；一级纯文字 + `≡ › ⋮` 三连 vs 圆图标 + 名称 + 数字角标 + 单 `⋮`；
  长短不一的自适应 chips vs 5 列等宽图标格；顶部一整段灰字常驻占首屏 vs 无常驻说明；
  无拇指区主操作 vs 胶囊容器 + 蓝色大 `+`；停用态拼进名字撑破 chip vs 不占文本。

数据侧复核（`assets/default_categories.json` version 4）：一级 15 / 二级 91，
启用 47 / 停用 59；**单个父级最多 11 个二级**（居住 11、餐饮 10、养车 9），
5 列即 3 行，完全放得下，不会出现 §7.3 担心的规模爆炸。最长名 7 字
「赡养·代缴水电」，需要固定格高 + 单行省略。
106 行的 `iconName` **全为空**、`colorHex` 恒为 `#888888`，
上彩色图标不是「读出来就行」，必须补一份图标数据。

## 做什么

1. **列表页借一羽布局**：蓝底 TopBar（返回 / 标题 / 右上「排序」+ ⋮），
   支出 / 收入 Tab 坐进标题栏下部；一级仍竖排 `LazyColumn` 行，
   行内为「彩色图标 + 名称 + 二级数角标 + 单 ⋮ 菜单」，
   `≡ / ›` 收进菜单；展开区二级改为 **5 列等宽彩色图标网格**，
   末位固定「添加子类」格；停用改为小角标，MUST NOT 再拼进名称；
   顶部说明灰字收进 ⋮ 的「使用说明」；底部胶囊容器放
   「已归档（N）/ 停用项管理」两个入口 + 蓝色大 `+` FAB 作主新增。
2. **新增独立「分类排序」页**（第 1 轮实现；**布局已被第 2 轮 1:1 重做取代，见下文 5**）：
   一级横排 5 列图标，选中一级的二级收进圆角白卡且用**灰阶单色**
   （一羽自己排序页就降饱和）；底部提示「长按拖动一级，点按拖动二级」+「保存」；
   **临时顺序与已落库 `sortOrder` 彻底分离**，保存时一次性写回，
   作用域仍是 `(type, level, parentId)` 三元组；放弃/返回 MUST NOT 静默写库。
   第 1 轮把白卡做成上下兄弟容器、二级排成一维列表以适配 `reorderable` 一维模型；
   第 2 轮撤回这两点，改为白卡插进网格中间 + 二级等宽图标格；
   第 3 轮技术核查后再撤回「必须自实现手势」这一错误判断，改为
   **两态互斥 + 两套 `rememberReorderableLazyGridState`**：
   拖一级时二级折叠，点开一级后白卡内二级 5 列网格独立拖。
   列表页始终是等宽网格。
3. **新增「分类选择」页**（借一羽「添加二级分类」页版式）：
   左侧分组导航 + 右侧等宽网格 + 顶部搜索 + 父级预填 + 「继续添加」，
   用于新增二级时选父级、以及批量挑选停用扩展项。
   **只借版式，不改语义**：不从预设分类库里「挑一个分类加进来」。
4. **放开彩色图标，按第 2 轮真机反馈重新划界**：分类管理三页（列表 / 排序 / 选择）
   + **记一笔「分类 ›」全量选择器 + 明细筛选「分类」选择器**
   SHALL 用本地图标目录呈现彩色具象图标；**记一笔快捷栏、明细列表行、
   账户详情、统计页 SHALL 保持中性圆 + 中文首字不动**。
   图标资源 MUST NOT 复制一羽的视觉资产，许可证审计写入 `design.md`。
5. **第 2 轮追加（v0.2.36 真机反馈）**：
   - 排序页按一羽图 3 **1:1 重做**：白卡插回一级网格中间、二级改 5 列等宽图标格；
     第 3 轮补定「拖一级时二级折叠、两级拖拽互不干涉」。
   - 抽取**只读**共享分类网格选择组件，替换记一笔与筛选的两处旧选择器；
     去掉名称输入框与「继续添加」按钮，原「分类选择」页（添加子类 / 连续添加）**完整保留**。
6. 同步修订 4 条已写死的 Requirement（按标题整块 MODIFIED，不留矛盾文本）
   + 新增 1 条 ADDED；并修订活文档 §2.6 / §7.3 的全局表述，
   明确「中性圆」口径收窄到快捷栏 / 列表行 / 账户详情 / 统计页：
   - `category-stats`「分类图标不做字符串映射」（第 2 轮再放宽适用范围）
   - `category-stats`「分类管理全量父级与排序」
   - `reporting-ui`「管理类页面入口固定且列表与编辑分离」
   - `reporting-ui`「分类全量选择器采用分组 chips 且不用下拉框」（**新增 MODIFIED**，
     标题沿用基线原名作整块替换锚点，正文改为分组导航 + 等宽网格）
   - 新增 `category-stats` ADDED「记一笔与筛选复用分类网格选择组件」

## 不做什么

- ❌ **不动记一笔快捷栏、明细列表行、账户详情、统计页**的分类标识
  （中性圆 + 首字照旧）。第 2 轮放行的彩色图标**只进四个页面/组件**：
  分类列表、分类排序、分类选择、记一笔与筛选的**全量分类选择器**。
  使用者 2026-11-23 明确勾选「新选择器图标走 A｜彩色 Tabler」，
  故放宽的是选择器，不是整页铺彩色图标。
- ❌ 不动两级数据模型、`AppDatabase.version`（仍 5）、`Migrations.ALL`（仍空）、
  DAO / SQL 出口、统计口径与环形图扇区配色：图标配色由图标目录常量提供，
  **MUST NOT 改写 `colorHex`**（该字段参与 `ChartData` 扇区取色）。
- ❌ 不动 `assets/default_categories.json` 的 ID 规则、启用/停用语义、
  备份整表替换、CSV / Firefly 按名称匹配路径。
- ❌ 不做「系统分类 / 分类扩展包」一键安装：底部胶囊只借位，
  换成已有的「已归档」「停用项管理」，不碰预置清单闸门。
- ❌ 一级列表**不横排**：横排只出现在排序页；列表页保持竖排 `LazyColumn`
  （第 12 批骨架），避免一屏塞不下 15 个一级。
- ❌ 不删除上移 / 下移（TalkBack 无障碍兜底）、不删改名 / 删除 / 看流水 / 停用五项操作。
- ❌ 不引入三级分类、账号体系、云同步、埋点、崩溃上报、远程配置 SDK。
- ❌ 不新增第三方 UI 库：等宽网格用稳定 `Row + weight(1f)`；
  一级与二级拖拽**都**用 `sh.calvin.reorderable:3.1.0` 的
  `rememberReorderableLazyGridState`（v3.1.0 README 一等 API，本仓库已在用），
  MUST NOT 自写 `Modifier.pointerInput` / `detectDragGestures*` 手势，
  MUST NOT 为此引入第二个 UI 库、MUST NOT 换库。
  两态互斥：同一时刻只有一个可拖容器，MUST NOT 让两个惰性网格嵌套；
  二级态外层一级区 MUST 为非惰性 `Column + Row(weight(1f))`，
  MUST NOT 用 `LazyVerticalGrid` 嵌进 `LazyColumn.item {}`
  （同方向嵌套滚动 + 高度不确定），
  MUST NOT 用 `@OptIn(ExperimentalLayoutApi)` 的 `FlowRow`（T12）。
  库 README 两条硬约束 MUST 遵守：`onMove` 返回前同步更新列表（否则拖动项闪烁）；
  容器内若插入任何非拖 item，`from.index` / `to.index` MUST 按 README 减偏移。

## 对齐结论

> 阶段 0 的产出。五项齐全才进入写作。
> 新会话只读这一节，即可还原本次改动的完整上下文，无需重新讨论。

1. **要解决什么问题**
   分类管理三页观感与操作路径明显弱于一羽记账，用其布局与交互逻辑优化；
   并纠正「等宽图标网格必然留白大」这一错误外推——真正的问题是
   前期 `WrapRow` 自适应 + 行尾留白 + 停用后缀拼进名称，不是网格本身。

2. **范围边界**（第 2 轮修订、第 3 轮技术澄清，覆盖第 1 轮）
   - 改：列表页布局（第 1 轮已完成，本轮不动）、**排序页 1:1 重做（两态互斥 +
     两套 grid state，不自实现手势）**、
     **抽取只读共享分类网格选择组件并接入记一笔「分类 ›」与筛选「分类」**、
     彩色图标适用范围放宽到选择器、修订 4 条 MODIFIED + 1 条 ADDED、活文档 §2.6/§7.3。
   - 不改：记一笔快捷栏 / 明细列表行 / 账户详情 / 统计页的分类标识、
     原「分类选择」页的添加子类 / 继续添加 / 父级预填 / 重名校验功能、
     两级模型、表结构、统计口径、清单 ID 规则、备份整表替换、5 个进行中 change 的 delta。
   - 详见上文「做什么」「不做什么」两节与文末「第 2 轮变更记录」「第 3 轮技术澄清」。

3. **关键约束**
    - 零改表 → v0.2.35 直接覆盖安装，不需要导出 / 卸载 / 导入。
    - 排序作用域固定 `(type, level, parentId)` 三元组，
      继续共用 `reorderable:3.1.0`（资产页仍用 `rememberKeyedReorder`，
      排序页一级 / 二级各用一套 `rememberReorderableLazyGridState`），
      松手 / 保存时一次性写 `sortOrder`；上移 / 下移保留为无障碍兜底。
      两套 grid state MUST 各管各段 `draftOrder`、同一时刻只有一个可拖容器。
   - 分类管理 MUST 保持「顶部固定入口 + 惰性列表 + 编辑独立视图」骨架
     与 `ListDivider()` 单一来源；可点区 ≥ 40dp。
   - 图标 MUST NOT 用 `iconName` 字符串在运行时反射 / 查表映射
     （T14 整份编译失败）；缺图标 MUST 回退中性圆 + 首字。
   - 图标资源 MUST NOT 复制第三方视觉资产；许可证与传递依赖审计须落盘。
   - 活文档 §1：CI 全绿不替代真机观感 / 性能 / 弹窗验证，
     本批 MUST 显式列出真机待验项并继承 §8 既有清单。

4. **验收标准**（第 2 轮重拟、第 3 轮补 1 条并改 2 条措辞，共 9 条，可测）
   > 使用者 2026-11-23 对第 4 问回「按你拟的」，故由本 change 拟一版，
   > 不是使用者逐字给出；确认时可直接改 / 砍 / 补。

    - **GIVEN** 进入分类排序页
      **WHEN** 长按一级手柄开始拖动
      **THEN** 二级区**折叠 / 不渲染**，页面只有 5 列一级网格，
      拖动让位与边缘滚动由 `reorderable` 负责，无 span item、无索引偏移
    - **GIVEN** 拖动结束后点某个一级
      **WHEN** 展开二级态
      **THEN** 圆角白卡**插在一级 5 列区中间**（选中行之后、其余一级行之前；
      二级态一级区为非惰性 `Column + Row`，视觉仍是插在中间），
      白卡内二级为 5 列等宽灰阶图标格、可独立拖；此时一级区冻结不可拖
   - **GIVEN** 在排序页拖动一级与二级、未点保存
     **WHEN** 按返回 / 放弃
     **THEN** 库内 `sortOrder` 零变化；点「保存」后一级只在支出一级间换位、
     二级只在所属父级内换位，收入与另一父级完全不变
    - **GIVEN** 一级态与二级态切换
      **WHEN** 分别拖动一级与二级
      **THEN** 两套 `rememberReorderableLazyGridState` 互不干涉：
      一级 `onMove` 只改一级段 `draftOrder`、二级 `onMove` 只改该父级下二级段，
      实时让位、边缘可滚、只改 `draftOrder`；上移 / 下移仍在供 TalkBack 使用
   - **GIVEN** 打开记一笔「分类 ›」与明细筛选「分类」
     **WHEN** 查看两处全量选择器
     **THEN** 复用**同一**只读网格组件：顶部搜索 + 左侧分组导航 + 右侧 5 列彩色图标格；
     **无名称输入框、无「继续添加」/ 保存按钮、无任何写库路径**
   - **GIVEN** 两个选择器中的「餐饮」
     **WHEN** 查看图标
     **THEN** 显示彩色 Tabler 图标；记一笔快捷栏、明细列表行、账户详情、统计页
     仍是中性圆 +「餐」字，`colorHex` 与环形图扇区配色零变化
   - **GIVEN** 选择器里存在停用项与归档项
     **WHEN** 打开并搜索
     **THEN** 停用一级 / 二级全部可见可搜并带「停用」角标、归档项不出现；
     按收支类型过滤；搜索跨组平铺且二级拼成「一级 / 二级」；
     点任一项立即选中并关闭、无二次确认，记一笔与筛选各自正确回填
   - **GIVEN** 从列表页「餐饮」行点「添加子类」
     **WHEN** 打开分类选择页
     **THEN** 父级 / 类型预填、搜索可用、「继续添加」可连续建二级、重名被拒
     —— 第 1 轮功能零回归
   - **GIVEN** 4 条 MODIFIED 与 5 条 ADDED 写完
     **WHEN** 跑归档校验与 CI
     **THEN** 无重复 Requirement 标题、每条 ≥1 Scenario、含 RFC2119、
     MODIFIED 按标题整块替换；零改表（version 5）、v0.2.36 可直接覆盖安装；
     CI 全绿**且**真机待验清单落盘（CI 不替代观感）

5. **被否决的方案**
   见 `design.md`「考虑过的其他方案」表。一句话结论：
    **撤回「不借鉴网格」「排序页用上下兄弟容器」「网格拖拽必须自实现手势」三条**；
    仍否决「一级列表也横排」、「彩色图标铺进记一笔快捷栏 / 明细列表行 / 统计页」、
    「扩展包一键装」、「改 `colorHex` 给图标上色」、「从预设库挑分类加进来」、
    「为了换库而新增第三方依赖」。
    第 3 轮核查 3.1.0 README 确认 `LazyVerticalGrid` 原生支持，
    「二维网格上硬做拖拽」不再是否决项，改为**按库原生 API 实施**。

## 与项目铁律是否冲突

对照 `openspec/project.md` 三条铁律检查：

- [x] **数据是你的**：图标资源全部随包本地，无网络请求、无回传；
  若引入可商用矢量集只作为本地资源，MUST 记录许可证与传递依赖审计。
  App 仍不声明 `INTERNET`，JSON 备份口令加密不倒退。
- [x] **账要算得准**：不碰 `colorHex`、不碰统计 SQL、不碰余额重算。

## 第 3 轮技术澄清（2026-11-23，排序页拖拽实现）

> 触发：使用者追问「排序除了 reorderable 没有现成的吗？一羽是怎么实现的。
> 一羽的排序在一级分类拖动排序时候二级分类是折叠起来的，reorderable 一级分类排序
> 和二级分类排序是否可以互不干涉，且由横排一个变成横排 5 个这种」。
> 本节只修订**排序页实现方案**，不改变第 2 轮已拍板的 1:1 视觉、彩色图标范围、
> 共享只读选择器、原分类选择页保留与验收口径（第 3 轮仅补 1 条、改 2 条措辞）。

| 核查项 | 结论 |
|---|---|
| 是否有现成替代库 | 有 `org.burnoutcrew:composereorderable`、JitPack `compose-reorderable:1.0.0`、`tomascrespo/Reorderable` fork；但两级折叠排序是**产品交互**，无库开箱提供，换库不解决问题且违背零新增依赖 → **不换** |
| 一羽怎么实现 | 一羽为闭源商业 App（Android / iOS / HarmonyOS + WebDAV），官网无源码与技术博客，**无法确认其具体库或实现**；只能按截图 + 使用者观察推断为「两态互斥」 |
| `reorderable` 是否只支持一维 | **否，上一轮判断错误，已收回**。3.1.0 README 明列 `LazyVerticalGrid` / `LazyHorizontalGrid` / StaggeredGrid，`rememberReorderableLazyGridState` 是一等 API；特性含不同尺寸 item、section headers、non-reorderable items、`animateItem` 让位、边缘自动滚动。本仓库 `CategorySortScreen.kt` 一级**本来就在用** |
| 两级能否互不干涉 | **能**。库状态按容器实例隔离；两套独立 `LazyGridState` + 两套 `rememberReorderableLazyGridState`，各自 `onMove` 只改自己那段 `draftOrder`；再叠加「拖一级时二级折叠」，同一时刻只有一个可拖容器 |
| 二级从横排 1 个变 5 个 | **能**，`GridCells.Fixed(5)` 原生支持跨行跨列换位 |

**方案定稿**：一级态 = 单个 `LazyVerticalGrid(Fixed(5))` 可拖、二级折叠不渲染；
二级态 = 非惰性 `Column` 手工 5 列 Row 展示一级（静态、蓝底选中），白卡插在选中行之后，
白卡内**第二套** `LazyVerticalGrid(Fixed(5))` + `rememberReorderableLazyGridState` 拖二级。
无 `GridItemSpan` 常驻、无索引偏移、无惰性套惰性、无自实现手势。

**仍需遵守的两条库约束**（README 原文）：`onMove` MUST 在返回前同步更新列表，
否则拖动项闪烁；容器内若插入非拖 item，`from.index` / `to.index` MUST 减偏移。

**分级判定不变**：扩展尚未归档的 `refine-category-management-pages`，
归档仍需使用者明确说「可以归档」。v0.2.36 已发布产物不受影响。
