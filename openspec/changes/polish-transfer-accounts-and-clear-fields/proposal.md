# polish-transfer-accounts-and-clear-fields

## 为什么

v0.2.59 真机反馈两条：

1. **「描述和备注框没有删除叉号」** —— 核查主 spec，
   `记一笔输入框紧凑且支持一键清空` 明文要求**交易对方 / 备注 / 账户搜索**
   三个输入框「有内容时显示尾部清空图标、点击立即清空、不撑到 48dp」。
   v0.2.59 实际只有交易对方有；描述是第 43 批新增字段时没跟上。
   更麻烦的是同一条 Requirement 后半段仍写着「『更多』展开区 SHALL 把备注与
   不计入开关放在同一 `FormRow`」「『更多』入口 SHALL 带 ⌄/⌃ 指示器」——
   第 80 批撤掉「更多」层时 MODIFIED 了 7 条，**漏了这一条**，
   主 spec 因此同时存在两条相反要求（踩坑清单 §4.3 文档腐化 / §4.2 归档不彻底）。
2. **「转账页面转出和转入账户不应该折叠，本来就是主要元素」** ——
   按 §7.41「把参考图当现状是最贵的误读」先分清：使用者给的是**一羽转账页**
   截图，我们 v0.2.59 转账态实际只剩类型 Tab / 金额 / 日期 / 描述 /
   5 枚 chips / 键盘，两张账户一眼都看不到，要点「转出/转入」chip → sheet →
   分段 → 再选。支出/收入态有 `LedgerPrefs.defaultAccountId` 兜底所以折叠成立，
   **转账没有这个前提**。与 §2.2「别靠卡片填满空白」不冲突：那说的是别加装饰，
   账户是主元素。

另追加第 4 问「原来 release 的 action 会上传坚果云，最近几次怎么没有了」，
核查结论见 `design.md` 决策 5：**不是配置回归，是本会话出包参数传错**。

## 改什么

- 抽 `ClearFieldIcon`（36dp 容器 + 18dp Icon），统一交易对方 / 描述 / 备注 /
  账户搜索四处一键清空：有内容才显示、点一下立即清空、不撑高 `heightIn(min=40.dp)` 行。
- 转账态首屏新增**两张中性卡片常驻**（转出 / 转入）：40dp 圆角图标容器 +
  主色 12% 底 + 账户名 + 余额小字，点哪张卡就把 `AccountPickerSheet` 锁到哪个
  target（`lockTarget`），sheet 内 MUST NOT 再出现转出/转入分段，避免双入口。
- 转账态 chips 由 5 枚改为 **4 枚**（移除「转出/转入」chip）；支出/收入态仍 5 枚。
- MODIFIED 掉 `记一笔输入框紧凑且支持一键清空` 里残留的「更多」过期段落，
  并把描述纳入覆盖范围；MODIFIED 4 条相关 Requirement、ADDED 1 条转账态条款。
- `check_workflow_syntax.py` 加两条可执行断言（坚果云默认值 / 步骤绑定），
  本批出包把 `upload_nutstore` 恢复为 `true`。

## 不改什么

- **支出/收入态账户继续在 chip**（使用者确认 ① 只改转账态）。
- **不做 ⇅ 互换**（使用者确认 ②，避免新增要验的手势）。
- 分类快捷栏、收款方联想条、描述首屏可见、金额真相源、模板预填草稿语义、
  标签关联表、统计口径、备份/CSV/Firefly 往返、4 Tab 导航。
- 一羽只借卡片观感，**不借业务字段**（不新增「报销 / 应付」类开关），
  MUST NOT 用阴影 / 描边 / 卡片堆叠（§7.41）。
- 零改表（`version = 8` 不变）→ v0.2.59 直接覆盖安装；
  零新增 Gradle 依赖（不引 `material-icons-extended`）、零 permission 变化。

## 对齐结论（阶段 0，五项）

| # | 项 | 结论 |
|---|---|---|
| 1 | 要解决什么 | ① 四处输入框一键清空一致，顺带修掉一条规格腐烂；② 转账态转出/转入账户从 chip 折叠改回首屏常驻，不再绕 sheet 分段 |
| 2 | 改什么 / 不改什么 | 见上两节。只改 `ui/record/` 的转账首屏、清空图标出口、两个静态脚本与文档；收支态账户、分类快捷栏、描述首屏、联想条、4 Tab、数据层、零改表全不动 |
| 3 | 关键约束 | 三条铁律；清空图标不撑高行（既有 32–44dp 基线）；转账两卡 MUST NOT 引入卡片阴影/堆叠；不新增业务字段；沙盒不编译 APK，走 GitHub Actions |
| 4 | 验收标准 | 12 个静态检查 + 单测 + Debug + Release lintVital 全绿；真机确认转账首屏两张账户卡直接可见可点、描述/备注/账户搜索有内容时出叉号且点一下清空、支出/收入态零回归；出包后核对「上传到坚果云」job step 为 success |
| 5 | 被否决方案及原因 | 账户继续留 chip 只把 sheet 默认展开（还是看不到两张卡）；两卡照搬一羽连同「转账到账金额 / 全部」一起搬（金额已在顶部，重复）；新做 ⇅ 互换（新增手势，使用者否决）；为对齐截图新增业务字段（§7.41）；详见 `design.md` |

**使用者三项确认**：① 只改转账态；② 不做 ⇅ 互换；③ 移除转账态「转出/转入」chip。
