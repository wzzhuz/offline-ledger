# 识屏记账能力规格

## 需求

在第三方账单页面通过系统快捷磁贴把当前这笔交易带进账本，减少手输；
不得静默写入、不得把账本数据传出设备。

## 场景

### 场景 1：节点文本命中

- **当** 使用者在白名单应用的账单详情页停留，且无障碍服务已开启
- **且** 下拉 QS 点「识屏记账」
- **则** 用内存里未过期的节点文本解析，跳过 OCR，确认页展示来源「节点文本」

### 场景 2：OCR 兜底

- **当** 节点快照为空或已过期
- **则** 透明页稳定后截单帧，端侧中文 OCR 提取文本块，确认页展示来源「OCR」

### 场景 3：明确降级

- **当** 截图返回安全窗口 / 节流 / 无服务，或解析不出金额
- **则** MUST 给可读原因 +「手动记账」入口，MUST NOT 写入任何记录

### 场景 4：确认后落库

- **当** 使用者核对后点「核对并保存」
- **则** 按 `importSource="screen"` + 结构化指纹幂等写入单事务，
  末尾重算余额；同一指纹第二次点保存 MUST 不重复入账

## 硬约束

- 无障碍服务 MUST 包名白名单；快照 MUST 只在内存且带 TTL
- 单帧 Bitmap MUST NOT 落盘 / 上传 / 进相册；识别后 recycle
- MUST NOT 声明 INTERNET 等网络权限；MUST NOT 引入回传类 SDK
- 磁贴 MUST 直接 `startActivityAndCollapse`，MUST NOT 绕广播再起 Activity
- 确认页 MUST 只读优先，MUST 经用户核对后才写
- 金额 MUST 整数分、BigDecimal 转换；MUST NOT 用浮点
- 表结构 MUST 零改动（`version = 5` 不变），覆盖安装
