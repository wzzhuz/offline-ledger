# 多币种基础（阶段 6c-1）

> **本文件是 change 的上下文入口。** 新会话只读这一份，就能还原本次改动全貌。

## 为什么改

**背景**：

- v2 规格书里点过：使用者在中国香港，大概率同时有 HKD / CNY / USD 账户。
  当时建议「v1 不做多币种，但 `accounts` 和 `records` 都要先留 `currencyCode`」。
  **6c-1 查证发现实现只做了一半**：`currencyCode` 只存在于
  `AccountEntity` / `BackupAccount` / `LedgerSnapshot` / `BackupEnvelope`，
  **`records` 表完全没有币种字段**，也没有汇率表
- 6c 四项在 `project.md` 全是「待决策」，且风险不同量级。
  使用者确认按推荐 A 拆批：**本轮只做多币种基础，严格不混算、不引入汇率**
- 使用者澄清隐私观（**本 change 最重要的上下文**）：

  > 「导出明文是可接受的，数据掌控在自己手里就可以，
  > 不可接受的是市场上 app 将数据保存在他们服务器上。」

  这**推翻了阶段 5「v1 不做 CSV」的决策依据**（当时理由是「CSV 明文导出
  与『导出文件默认加密』张力最大」）。结论「本批不做 CSV」保留，
  但错误论据必须从 specs 里清掉，否则以后开 CSV 会被一条使用者否定的理由拦住
- 使用者提出一个很关键的问题：**「当前应用还处于开发阶段，没有历史数据，
  数据库迁移是什么？」** 详见 `design.md` 第 0 节；结论是此前几轮把
  「三次叠加迁移」的风险描述**过重了**，本 change 如实修正，不粉饰

**问题**：`records` 没有币种 → 统计与资产页无法按币种分开，
HKD 与 CNY 的支出会被加在一起，回答不了「哪类支出比较多」。

## 做什么

1. **口径修正**：`project.md` 铁律 1 补隐私边界；闸门把 6c 拆成 6c-1 / 6c-2；
   小组件、通知栏磁贴与跨币种混算移入「永久不做」；CSV 理由改写
2. **2 份 MODIFIED**：`backup-restore`「CSV 格式约定」、
   `privacy-security`「导出文件默认加密」——删除以「明文风险」为前提的约束
   与阶段版本号绑定，保留「JSON 备份已加密」的已交付能力
3. **数据层**：`records` / `trash` 加 `currencyCode`（从账户继承），
   `Migration(3→4)`，备份 `CURRENT = 4` / `MIN_SUPPORTED = 1`
4. **写入正确性**：记一笔 / 模板 / 周期补记 / 报销 / 覆盖导入
   都把账户币种写进流水；**转账仅允许同币种**，跨币种 MUST 被拒
5. **展示（严格不混算 A′）**：资产页按币种分组列各币种小计，
   **移除单一「净资产」总数**；统计页加币种切换，只统计所选币种
6. **统计查询**：新增一组 `...ForCurrency` 查询，
   **既有 12 条聚合 SQL 与 `StatRules` 常量一行不动**（沿用 6b 的展示层隔离思路）
7. 纯 JVM 单测覆盖币种继承、同币种转账、v1/v2/v3 备份兼容、
   `Migration(3→4)` SQL 契约；静态检查扩到 `version = 4` 与三段迁移

## 不做什么

- ❌ **不做跨币种混算、不引入汇率表、不算「折算后净资产总数」**
  （6c-1 明确排除，移入永久不做候选）
- ❌ **不做 CSV 导出 / 账单导入 / 自动记账**（6c-2 待决策）
- ❌ **不做小组件 / 通知栏磁贴**（移入永久不做）
- ❌ **不把已加密的 JSON 备份降级为明文**（使用者说「明文可接受」
  不等于「要把已有能力拆掉」；保留已交付能力，只是不再拿它当禁令）
- ❌ 不改既有 12 条聚合 SQL、不改 `StatRules.SQL_STAT_RELEVANT`、
  不改 4 Tab 导航、不改 Manifest 权限、不改 `release.yml`
- ❌ 不引入任何新依赖、不申请任何新权限、不新增网络行为
- ❌ 不用 `fallbackToDestructiveMigration`
- ❌ 不改历史快照 `docs/设计规格书_v2.md`、`my-app-workflow`

## 对齐结论

> 阶段 0 在对话里产出，五项齐全才进入写作。
> 使用者回复「1. 按推荐来。」即确认 A + A′ + A。

1. **要解决什么问题**
   `records` 补上币种，让「资产情况」与「哪类支出多」能按币种分别回答；
   同时把使用者澄清的隐私边界写进项目约定，消除 specs 里被推翻的错误论据。

2. **范围边界**
   - 改：闸门 / 铁律 1 / 2 份 MODIFIED / 2 张表加列 / `Migration(3→4)` /
     备份 v4 / 写入侧币种继承 / 同币种转账校验 / 资产页分组 /
     统计页币种筛选 / 10 条新查询 / 静态检查 / 单测
   - 不改：6c-2 全部、既有 12 条聚合 SQL、唯一统计口径常量、
     4 Tab 结构、记一笔 / 明细 / 对账 / 预算 / 报表的既有行为、
     构建链、Manifest 权限、历史快照

3. **关键约束**
   **闸门**：6c 拆批，只放行 6c-1；`reporting-ui`「v1 范围收敛」不改
   （描述 v1 历史范围，仍成立）；小组件 / 通知栏磁贴 / 跨币种混算
   移入「永久不做」并写明原因。
   **隐私边界**：不可接受的是数据上传厂商服务器；
   **本地导出明文不违规**。JSON 备份保持已实现的口令加密，不倒退。
   **严格不混算**：资产页 MUST 按币种分组列小计，
   MUST NOT 显示单一净资产总数；统计页 MUST 提供币种切换且默认选中一个币种，
   MUST NOT 跨币种聚合；转账 MUST 校验两账户币种一致。
   **金额铁律不破**：`amountCents` 仍恒为 `Long` 分，
   币种只是 ISO 4217 字符串标签，不参与任何加減；
   `aggregateAccountDeltas()` 与余额重算 MUST NOT 按币种过滤
   （按币种过滤会算错账户余额）。
   **查询隔离**：新增 `...ForCurrency` 查询都 MUST 带
   `excludeFromStats = 0` 与 `currencyCode = :currencyCode`；
   纳入 `check_stat_rules.py` marker 清单；既有 12 条 SQL 一行不动。
   **迁移**：显式 `Migration(3→4)` = 两条 `ALTER TABLE ... ADD COLUMN
   currencyCode TEXT NOT NULL DEFAULT 'HKD'`；
   `ALL` 含三段；仍禁止破坏性迁移。
   **备份**：`CURRENT=4`、`MIN_SUPPORTED=1`，v1/v2/v3 备份仍可导入；
   信封四项头部一字不改；`BackupRecord` 新字段带默认值。
   **真机验证继续推迟**（使用者 A）：`design.md` 重写累积清单，
   并修正此前「三次叠加迁移」的过重措辞（见第 0 节）。
   六个静态检查全过；推送单次 commit；沙盒无 SDK，编译与单测由 Actions 验证。

4. **验收标准**（可测）
   - **GIVEN** HKD 微信支出 38.50 与 CNY 支付宝支出 20.00 **WHEN**
     统计页切到 HKD **THEN** 支出合计 38.50、不含 20.00
   - **GIVEN** 两账户币种不同 **WHEN** 打开资产页 **THEN**
     按 HKD / CNY 分组列小计，**没有**单一净资产总数
   - **GIVEN** HKD 账户向 CNY 账户转账 **WHEN** 保存 **THEN**
     被拒绝并提示「转账双方币种必须一致」
   - **GIVEN** v1 / v2 / v3 加密备份 **WHEN** 用 6c-1 包导入 **THEN**
     全量一致、旧流水币种默认 HKD、余额重算后各账户余额一致
   - **GIVEN** 归档 **WHEN** 校验 specs **THEN** 2 份 MODIFIED 按标题替换、
     无「明文风险」错误论据、闸门已放行 6c-1
   - **GIVEN** CI 跑完 **THEN** 六个静态检查、单测、debug/release 全绿

5. **被否决的方案**
   一句话结论：**所有「四项全做 / 引入汇率折算 / 把 JSON 降级成明文 /
   改既有 12 条聚合 SQL / 按币种过滤余额重算 / 绕过闸门直接写 /
   破坏性迁移」的方案均被否决**，采用「拆批 + 2 份 MODIFIED 修正论据 +
   流水币种继承 + 独立 ForCurrency 查询 + 严格不混算 + 显式 Migration(3→4)」。
   完整表格见 `design.md`「考虑过的其他方案」。

## 影响范围

**触及的 spec 模块**：`money-precision`、`ledger-transactions`、
`backup-restore`（含 1 MODIFIED）、`privacy-security`（含 1 MODIFIED）、
`reporting-ui`、`category-stats`、`build-and-ci`；合计 ADDED + 2 份 MODIFIED。

**是否需要重新安装包**：否，签名未变。
**是否会丢数据**：设计上否；但见 `design.md` 第 0 节——
**使用者至今从未装机，三段迁移从未在真机执行过**，
且按他的用法（直接装最新版）首次装机根本不触发任何迁移。
