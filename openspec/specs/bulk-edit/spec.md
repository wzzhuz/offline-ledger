# bulk-edit Specification

## Requirements

### Requirement: 批量规整采用动态规则编辑器且可逐字段撤销
规则 SHALL 由「字段 ▾ + 操作符 ▾ + 按类型分派的值控件」的动态行编辑器产生，
MUST NOT 以固定槽位表单枚举可用条件与动作。条件字段 SHALL 至少包含交易对方、
分类、备注、金额、账户、日期、币种、导入来源、不计入收支；操作符 SHALL 按字段动态给出，
并支持取反与 ALL / ANY。动作 SHALL 支持设置分类、交易对方改为、备注替换 / 追加、
切换不计入收支，一条规则可叠多个动作。

分类与账户的值 MUST 由弹窗按 id 选择（含停用与归档项，显示「一级 / 二级」），
交易对方与备注 MUST 提供 DAO 限量联想；MUST NOT 靠键盘手打目标分类名，
否则 v0.2.14 换过分类清单后必然对不上名。规则 MUST 可保存、按组内 sortOrder 有序、
可启停 / 编辑 / 复制 / 删除；「保存并立即应用到历史」SHALL 在保存后直接走同一
预览 → 单事务 → 末尾重算 → 撤销链路。

规则列表 SHALL 为独立全屏页，编辑器 SHALL 为另一独立全屏页，两者 MUST NOT 同页滚动堆叠；
规则列表 MUST 提供设置一级入口（排在「数据与备份」之后），「数据与备份」内 MUST NOT 再保留
「批量调整 / 批量规整」入口；拆页 MUST NOT 新增 NavHost 路由或动 4 Tab 骨架。
已保存规则 MUST 可从列表再次「应用」到历史记录，应用 MUST 先进入「查看匹配记录」页给出
命中数与前后对比，确认后 MUST 走同一单事务 → 末尾重算 → changeset 逐字段撤销链路；
「查看匹配记录」MUST NOT 被当成规则详情，「编辑」才是唯一详情入口；列表 SHALL 显示上次应用结果。

分类调整 SHALL 直接就是一条普通规则（条件 = 分类等于旧类 → 动作 = 设置分类为新类），
通过字段下拉与分类弹窗按 id 选值完成；MUST NOT 再提供「批量录入 / 映射表」入口或
任何文本解析器。第 39 批及此前由批量录入生成的规则都是普通 `rule_definitions` 行，
删入口 MUST NOT 丢失这些已存规则，它们照常可编辑 / 应用 / 复制 / 删除。

规则编辑器 MUST 提供「查看匹配记录」入口，用**当前未保存草稿**的条件只读求值，
给出命中数与前后对比，MUST NOT 要求先保存、MUST NOT 在预览时落库或生成 changeset；
草稿预览与列表「应用」MUST 复用同一预览页与同一 `previewRule` 求值出口，
从草稿进入时返回 MUST 回到编辑器，从列表进入时返回 MUST 回到列表。

所有写入 SHALL 先给出命中条数与前后对比，确认后 MUST 在单事务内写入并末尾重算；
变更 MUST 生成 `changeset` 保存每个受影响字段的变更前值，撤销 MUST 逐字段还原。
禁止静默改写历史；一期禁止导入后自动触发、嵌套条件、表达式引擎与 stop processing。

#### Scenario: 旧分类一次迁移到新分类
- **WHEN** 使用者配置「条件 = 分类等于旧类 → 动作 = 设置分类为新类」并保存后立即应用
- **THEN** 该旧类下全部流水改为新类，前后对比与撤销逐字段一致

#### Scenario: 同名二级不串味
- **WHEN** 两个不同一级下都有名为「其他」的二级分类
- **THEN** 分类弹窗显示「一级 / 二级」全名，按 id 选中，命中集合互不混淆

#### Scenario: 条件互不串味
- **WHEN** 同时设置对方包含、分类等于、金额区间与导入来源
- **THEN** 只命中同时满足全部条件的记录；任一条件留空不会命中全库

#### Scenario: 编辑草稿时直接查看匹配记录
- **WHEN** 在规则编辑器改完条件、尚未保存时点「查看匹配记录」
- **THEN** 用当前草稿只读求值并展示命中数与前后对比，账本与规则表均无写入；
      返回后仍在编辑器，草稿内容不丢

#### Scenario: 删批量录入不丢已存规则
- **WHEN** 移除「批量录入 / 生成规则并看命中报告」入口后打开规则列表
- **THEN** 此前由批量录入生成的规则仍在列表里，可编辑、应用、撤销与删除
