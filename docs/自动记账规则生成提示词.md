# 自动记账规则生成提示词（离开本会话也能用）

> 第 88 批。用途：以后遇到「这一笔没有自动记上」，不需要再找我攒样例，
> 也不需要自己写规则。把下面的提示词复制给任意 AI，它会回你 1~3 行可粘贴的规则。

---

## 一、什么时候用

- 分享进来后页面显示「未达标 / 已降级草稿」，而不是「已记账」
- 设置 → 自动记账 / 文本诊断 → 规则与试解析 → 粘贴原文试解析，看到某个字段未命中
- 支付宝改版后，出现了新的状态词、新的优惠叫法、新的噪声行、新的账单分类

**不用**在一切正常时使用：默认规则已随 APK 打包，六笔实测原文都能自动落库。

---

## 二、可复制的完整提示词

```
你是「离线账本」Android App 的自动记账规则助手。

我会贴一段从手机系统「全选 → 分享」得到的账单原文（我会先手动删掉订单号、卡号尾号等敏感信息），以及 App 里显示的「未达标」提示。

当前默认规则基线：
- 状态词：交易成功 / 自动扣款成功 / 支付成功 / 付款成功
- 优惠词：红包 / 立减 / 券 / 满减 / 折扣 / 优惠 / 减免
- 噪声：账单管理 / 支付奖励 / 收单机构 / 清算机构 / 标签 / 请选择 / 为您推荐 / 计入收支 / 备注 / 添加 / AA收款 / 查看往来记录 / 对此订单有疑问 / logo / arrow / extend-icon 等
- 分类映射：餐饮美食 = 餐饮
- 本项目一级分类只有：餐饮 / 交通 / 养车 / 居住 / 购物 / 医疗 / 学习娱乐 / 宠物 / 人情社交 / 其他

任务：判断这段原文为什么没有达到自动落库门槛，只输出需要增补的规则行。每行一条，不要解释、不要输出正则 / JSON / 代码 / 其他文字。

只允许这四种格式：
状态词 += 新状态词
优惠词 += 新优惠关键词
噪声 += 新噪声行
分类 支付宝账单分类 = 本项目一级分类名

约束：
1. 只增补词表与分类映射，不要改金额规则、主金额位置、优惠算术校验或自动落库门槛。
2. 没有对应的一级分类就不要输出分类映射，留空让我自己配；不要硬猜。
3. 若失败原因是字段位置 / 区块结构变了，而不是某个词没覆盖，只输出一行：# 结构变化，需要改代码并发版
4. 最多 3 行；多个词可用中文逗号写在同一行。

示例输出：
状态词 += 自动扣款成功
优惠词 += 立减金
```

App 内也有同一段：设置 → 自动记账 / 文本诊断 → **规则与试解析** 页 → 规则增补 → **「复制规则生成提示词」**，
手机上不用翻 GitHub 文档即可复制。两处内容由 `check_text_intake.py` 断言关键句一致。

---

## 三、使用步骤

1. 在识别页点 **「复制全文」** 拿到原文
2. **先手动删掉**订单号、商家订单号、卡号尾号（见下方隐私提醒）
3. 打开任意 AI 会话，粘贴上面整段提示词，再贴处理后的原文 + 「未达标」提示
4. AI 只回 1~3 行，例如：

   ```
   状态词 += 自动扣款成功
   优惠词 += 立减金
   ```

5. 回到 App：设置 → 自动记账 / 文本诊断 → **规则与试解析** 页 → 规则增补框粘贴 → 点 **试解析**
6. 把同一段原文贴进试解析框，看「严格门槛」是否变 ✓
7. 生效即时，不用等出包；点 **恢复默认规则** 可一键回基线

规则覆盖层只存在本机 `LedgerPrefs`，不进 Room、不进备份、卸载即回默认。
覆盖层**不会**改金额正则、主金额锚点、优惠算术校验、自动落库门槛；
一段坏规则最多让某笔降级草稿，不会造成误记。

## 四、四种指令（只允许这四种）

| 指令 | 用途 | 例 |
|---|---|---|
| `状态词 += X` | 新的支付成功 / 扣款成功文案 | `状态词 += 自动扣款成功, 付款完成` |
| `优惠词 += X` | 新的优惠叫法（按关键词匹配） | `优惠词 += 立减金` |
| `噪声 += X` | 新的 UI 文案、推荐 chips、图标占位符 | `噪声 += 查看购物详情` |
| `分类 A = B` | 支付宝账单分类 → 本项目一级分类 | `分类 餐饮美食 = 餐饮` |

多个词可用中文逗号写在同一行；`#` 开头与空行忽略；非法行会显示「已忽略 N 行无效指令」。

**本项目一级分类只有**：餐饮 / 交通 / 养车 / 居住 / 购物 / 医疗 / 学习娱乐 / 宠物 / 人情社交 / 其他。
支付宝的「亲友代付」「文化休闲」「公共服务」没有对应一级，**不要硬猜**，留空由自己在映射表里配。

## 五、什么情况不能靠提示词解决

以下属于**结构变化**，覆盖层只增补词表，修不了，需要把原文贴回本会话改代码并发版：

- 状态锚点不再排在「商户名 → 主金额 → 状态行」这个顺序
- 金额区块整体移位，或标签与值不再分行
- `订单号` 改成别的标签，或不再有 20 位以上纯数字订单号
- 页面特征行（账单管理 / 收单机构 / 商家订单号 等）大面积消失
- 换成微信支付成功页等**另一种页面**（本项目目前只适配支付宝账单详情）

AI 遇到这类情况只会输出一行 `# 结构变化，需要改代码并发版`，看到它就别再试规则了。

## 六、隐私提醒（重要）

整屏原文含**商户全称、卡号尾号、完整订单号、商品说明**。把原文贴给外部 AI，
等于把这段文本发给第三方服务——这与本 App「不声明 INTERNET、数据只在本机」是两回事，
但**是使用者主动、可控的一次导出**，项目红线禁止的是「默认回传且用户无法控制」，不包括这一下。

建议贴之前手动删掉：

- `订单号` 后面那一串 28 位数字
- `商家订单号` 后面的长数字与掩码行
- `付款方式` 里的卡号后四位
- 收单机构 / 清算机构全称（可选）

**只保留**商户名、金额、状态词、时间、优惠标签、账单分类和「未达标」提示，
足够让 AI 判断该加哪一行词。App 本身不上传、不联网、不写这些原文到任何文件。

      标签 / 请选择 / 为您推荐 / 三餐 / 买软件 / 下馆子 / 代付 / 计入收支 /
