# Firefly III 导出导入 · 字段说明

适用版本：**Firefly III 6.6.x**（以 6.6.6 实测导出为准）。
在 Firefly III 导出页面生成 `YYYY_MM_DD_transaction_export.csv`，
用系统文件选择器选中即可；应用不联网、不申请任何权限，文件只在本机读取。

## 表头与用到的列

导出共 53 列，导入**按列名定位**、顺序无关；只读取下表这些列，其余忽略。

| 列名 | 中文含义 | 本项目怎么用 |
|---|---|---|
| `journal_id` | 流水号 | 写入 `sourceId` 唯一键；备注也保留 `ff3:<id>` 便于肉眼追溯 |
| `group_id` / `group_title` | 交易分组 / 组名 | 组名写进备注，便于查拆分交易 |
| `type` | 交易类型 | Withdrawal→支出、Deposit→收入、Transfer→转账、Opening balance→账户期初；Reconciliation 跳过 |
| `amount` | 金额 | 支出为负、收入/转账为正；流水取绝对值转「分」，期初保留符号 |
| `currency_code` | 币种 | 样本全为 CNY；币种由账户继承，不混算 |
| `foreign_currency_code` / `foreign_amount` | 外币 | 有值且不同于主币种时给提示，仍按主币种落账，**不做汇率折算** |
| `date` | 交易时间 | `2026-11-15T11:22:00+08:00`，含具体时分；归到 Asia/Shanghai 的日/月 |
| `description` | 摘要 | 写进备注开头 |
| `source_name` / `source_type` | 来源账户 / 类型 | 支出的付款账户、收入的付款方、转账的转出账户 |
| `destination_name` / `destination_type` | 目标账户 / 类型 | 支出的收款方、收入的入账账户、转账的转入账户 |
| `category` | 分类 | `一级-二级` 格式（如 `食-堂食`），按第一个 `-` 拆成两级 |
| `tags` / `notes` / `budget` | 标签 / 原备注 / 预算 | 有值就写进备注；本项目没有标签系统、不导入预算 |

## 四类交易怎么落

| FF3 | 本项目 | 账户 | 交易对方 |
|---|---|---|---|
| Withdrawal | 支出 | source_name | destination_name（收款方） |
| Deposit | 收入 | destination_name | source_name（付款方 / 来源） |
| Transfer | 转账 | source→destination 双账户 | 不显示 |
| Opening balance | 不进流水 | 非初始余额账户那侧 | 不显示 |

## 账户与分类映射

- **账户**：默认同名自动映射到已有账户；没有就按名称建议类型新建
  （信用卡/花呗/月付→信用负债，加油卡/充值卡→储值卡，证券/基金→投资理财，其余资产）。
  每一项都能在预览页改成映射到别的已有账户，或改回新建。
- **分类**（第 74 批）：按 `一级-二级` 拆开，支出与收入各建各的树。
  每一项点「选择分类」打开**全量只读选择器**（搜索 + 左分组导航 +
  右彩色图标网格），可映射到任意预制或已有的一级 / 二级分类，
  **按 id 精确落位**、不再按名字匹配；同名一级会自动预填。
  「⋯」里只保留「按原名自动新建」「不设分类」两个动作，不逐个列分类。
- **期初余额**（第 74 批）：新建账户直接用导出值；映射到已有账户时
  由三态策略决定，默认「保持」。
  - **保持**：完全不动已有账户的期初，FF3 期初行计入跳过报告。
  - **覆盖**：把 FF3 期初写入 `initialBalanceCents`。改名映射同样生效，
    但已有流水的账户会**整体平移历史余额**、已对账余额也会变。
  - **差额调整**：不改写历史起点，按「FF3 期初 − 当前期初」走既有
    调整机制；最终余额与「覆盖」一致，但已对账余额不变。
    第二次导入同一份文件不会重复累加。
  预览页每个已有账户都会显示「当前期初 ¥X · FF3 期初 ¥Y / 无（不动）」。

## 不会导入的数据

规则、订阅、附件、存钱罐、标签系统、预算、汇率折算、复式分录、外部对方账户建账户。
这些要么本项目没有对应概念，要么会破坏「数据不混算 / 对方不建成账户」的边界。

## 幂等与回滚

同一份文件选两次：第二次按数据库里的 `importSource = FIREFLY_III` 与
`sourceId = journal_id` 复合唯一键全部跳过，不会重复记账；
删掉备注前缀也不会破坏幂等。自有 CSV 导出同样带这两列，清库后原样导入可重建。
导入在**单个事务**里完成，任一行非法（账户未映射、转账缺转入、金额非正）整体回滚，
账本保持原样；成功后统一重算所有账户余额。

⚠ **当前 `AppDatabase.version = 7` 且未注册 Migration，覆盖安装会开库失败**：
（第 22 批首次引入时为 `version = 2`，此处按现行状态订正）
先在「数据与备份」导出 CSV 或加密备份带走现有数据，卸载旧版、安装新版，
再用「导入账单」重建；**不要覆盖安装**，否则开库会失败。
